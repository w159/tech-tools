# Atlas Mod (Claude Code mods) plan
Date: 2026-10-09
Owner: atlas-plan
Goal: Bring the atlas Colony, the IRC channel, the TODO board, the persona roster and the operating-contract progress into the Claude Code terminal. The mod should carry Atlas branding, give each persona its own pixel character, and draw a contract progress track that is always on screen.

Status: design only. Nothing is implemented yet. Every claim about the mods API comes from the docs
(`code.claude.com/docs/en/plugins/mods/{overview,interface,api,events,reference,create}`)
or from strings in the installed binary (2.1.293 when written; 2.1.296 now). Items that still need proof are listed
under "Assumptions vs proven", and the spike stage proves them.

## DECISION NEEDED (FYI, each default already taken)
1. **Packaging.** Default: ship the mod inside the atlas plugin, as a `modules` entry
   in the existing `plugins/atlas/hooks/hooks.json` (the reference allows `modules` and
   `hooks` in one file). The kill switch is `ATLAS_MOD=off`, matching `ATLAS_CHANNELS=off`.
   Alternative: a separate opt-in plugin, `plugins/atlas-mod/`.
2. **Effort source of truth.** Default: Claude frontmatter in `plugins/atlas/agents/*.md`.
   Conflict: `atlas:implementer` is `effort: low` in Claude frontmatter but has
   `thinkingLevel: medium` in `omp/atlas-agents.ts:38`. The mod copies the frontmatter
   value and flags the mismatch on the Squad tab.
3. **Header format change.** Default: add an optional `n/m` segment to the header
   (`ATLAS | 🔧 implement 3/5 | ...`) and widen `headerFirstLinePattern` to match it. See section 6.

## 1. What Claude Code mods give us (2.1.287+)

A mod is a plugin whose `hooks/hooks.json` names a JS/TS ES module that exports
`register(on, options)`. The module runs in-process. It has no Node APIs: all file,
process and network access goes through `$`.

| Capability | API | Atlas use |
| :- | :- | :- |
| Sidebar or inline pane with tabs, buttons, inputs, selects | `$.ui.open`, `ui.render {component:'Pane'}` | Command Center pane |
| Always-on band above the prompt | `ui.render {component:'AbovePrompt'}` | Contract track and squad strip |
| Restyle Claude Code's own UI | `Spinner`, `ToolUse`, `AssistantMessage`, `TurnDuration`, `PromptHint` | Phase-aware spinner, persona chip on Agent rows, header restyle |
| 24-bit colour pixel grid, animated in place | `Raster` (<=512x256 cells), `$.ui.blit` | Spinner globe, title logo, sprite sheet (non-interactive art only; see sprite architecture) |
| Animated, interactive region with its own frame clock | `Client` (`surface.every`, `onPointer`, `onKey`, `post`) | Band, Colony diorama, Board kanban, Squad portraits |
| PNG in terminal; SVG in Desktop | `Image`, `Svg` | Logo splash; Desktop sprite fallback |
| Instant commands, usable mid-turn | `$.command.register({immediate:true})`, `command.run` | `/atlas`, `/atlas-say`, `/atlas-todo` |
| Timers | `$.clock.every` | 1.5 s file poll (the API has no fs.watch) |
| Files and processes | `$.fs.read/list/stat`, `$.process.run` (argv, no shell) | Read `.atlas/.run/*`; call the `atlas_todo.py` and `atlas_herdr.py` CLIs |
| Subagent lifecycle | `agent.spawn` (rewrite `model` or `{deny}`), `$.agent.list()` (status pending/running/waiting/idle/completed/failed/killed) | Persona routing, live roster |
| Per-request model/effort | `turn.step` with `e.agentId`: `next({...e, effort})` | Enforce persona effort on forks, which today inherit the parent's effort |
| Token usage per request and turn | `turn.step` result usage, `turn.complete` `e.usage`/`e.answer` | Per-persona token meter; header parsing |
| Notifications | `$.ui.toast`, `$.ui.log` | Agent finished or failed, note to lead, todo completed |
| Reactive and persisted state | `$.state` (survives module reload; reset by `/clear`, `/resume`, `/branch`, so reload it from `classic.SessionStart` with `source` clear/resume/fork) | Pane tab and filters |
| Persisted store | `$.store` (4 MiB, cross-session) | Sprite seed and preferences |
| Limits | redraws are throttled to 10/s, or 30/s in the terminal for the visible pane, expanded band and hint line; hook CPU 10 s; `$.fs.read` 4 MiB | Throttle is fine; board JSONL is read with a per-file size cursor |

Where it runs: the CLI and the Desktop Code tab. `Raster` and `Image` are terminal-only,
so the Desktop gets the `Svg`/`Text` fallback. `claude -p` and the Agent SDK **do** run mod
hooks but draw nothing (overview, "where mods run"). So the `agent.spawn`/`turn.step` persona
routing also applies inside headless `claude -p` colony workers, and every `ui.*` hook must
no-op cleanly there. omp is a separate harness. The existing omp twin `omp/channel-view.ts`
stays as it is.

## 2. Data plane (read-only; no daemon, no dashboard dependency)

All data comes from `<root>/.atlas/.run/`. `root` is `ATLAS_PROJECT_ROOT` if set, otherwise
the nearest ancestor that contains `.atlas`. This is the `boardRoot` rule in
`omp/channel-view.ts:74-80`. `atlas_todo.find_root` (`scripts/atlas_todo.py:149-162`) differs:
it stops at the first `.git`/`.atlas`/`docs`, maps a linked worktree to the main root, and walks at most
7 levels. The mod follows `boardRoot`, and the worktree mapping is a stage 0 check.

The walk uses `$.fs.exists(dir + '/.atlas')` at each level. `$.fs.ancestors` cannot replace it,
because it only looks for relative `.md` file names (`FsAncestorsRequest.names`) and cannot find a
directory. The mod's own scripts resolve from `$.plugin.root`. That is a plain string property (the
absolute plugin directory), not a method, so `$.plugin.root + '/scripts/…'` is correct as written.

| Surface | Source | Read rule |
| :- | :- | :- |
| TODO board | `todos.json` `{version, items[{id,content,status,owner,session_id,phase?,archived,evidence}]}` | Filter `session_id == $.session.id()` and `!archived`, plus in_progress items owned by channel members. Phase comes from `phase` or the content prefix `[<phase>] ` (`contracts/operating-contract.json` `itemPhasePrefix`). The file is replaced atomically, so poll `$.fs.stat` mtime. |
| IRC channel | `board/<owner>.jsonl` lines `{ts,seq,owner,to,item,text,channel,kind?,delivery?}` | Filter `channel == <lead channel>` and sort by `seq,ts`. This ports `readChannelNotes`/`formatNote` from `omp/channel-view.ts:63-114`. Keep a per-file byte cursor using `stat.size`. **Never call `atlas_todo.py inbox`** from the viewer: it drains the lead's mail. |
| Channel roster | `channels.json` `channels[name].members[{name,role,pane_id,pid,ended_at,exit_code}]` | Find the lead channel: the entry whose `lead` equals `lead-<sid6>` (`hooks/session_boot.py:822-837`). Otherwise fall back to `<folder>@<branch>`. |
| Colony panes (herdr) | herdr unix socket; `$.http` cannot reach it | `$.process.run(['python3', $.plugin.root + '/scripts/atlas_herdr.py', 'status'])` every 5 s. Only while the Colony tab is visible. |
| In-session subagents | `$.agent.list()` plus `agent.spawn`/`turn.complete` events | Native and instant. This is the primary source for Task subagents. |
| Personas | `plugins/atlas/agents/*.md` frontmatter (`model`, `effort`, `color`) via `$.fs.read` at `session.start` | One source; no copied table |
| Contract | `contracts/operating-contract.json` (`phases[].id/glyph`, `todoPhases`, `headerFirstLinePattern`) | Track order and header regex |

Merged member state reuses the dashboard states (`scripts/atlas_dash_colony.py:12-13`, `parked` at :406):
running, idle, stuck (`STUCK_S` 15 min, :38), parked, finished, dead. The mod adds
**input** from herdr `agent_status: blocked`, which is the same mapping as
`scripts/dashboard_ui/js/glyphs.js:23`.

## 3. Surfaces and visual design

Brand tokens come from `scripts/dashboard_ui/css/tokens.css:3-32`: accent `#2fbd9f`,
bg `#0c1215`, surface `#121a1e`, text `#e6edf0`, dim `#9fb0b8`, ok `#52c872`,
working `#62b8e6`, input `#f2aa40`, fail `#ff7570`, idle `#93a4ac`, subagent `#b5a3fa`.
The mark is the dashboard hex-cube (`index.html:31`). Its text form is `⬢`, and
`Raster` renders it as a 7x7 sprite.

The first draft only coloured text in the band and the pane. That is the cheapest use of
mods. This version is built on the three elements that make mods look alive:
- **`Client`**: a region drawn by a second module, with a frame clock (`surface.every`), local
  state, pointer input (down, move, up, enter, leave, with sub-cell `fine` x/y on iTerm2,
  kitty, Ghostty and WezTerm) and key input (`surface.onKey`). It talks to the hooks module
  through `surface.post`, which arrives as `ui.message`.
- **`Raster`**: a 24-bit pixel grid up to 512x256 cells, repainted at frame rate with `$.ui.blit`.
- **Pointer hover**: `hover` and `scope` on `Box`/`Text`. Hovering one element can reveal
  another, absolutely positioned `Box` in any site, with no hook running.

All facts above come from the generated types for 2.1.293
(`.claude-plugin/types/claude-code/index.d.ts`: `ClientSurface`, `ClientPointerEvent`,
`ClientProps`, `TextProps`, `BoxProps.hover` with `BoxHoverProps.scope`/`TextHoverProps.scope` and
`position: 'absolute'`, `ImageProps`, `SvgProps`).

**Sprite architecture (decided).** `ClientElements` excludes `Raster` and `Image`, so there are
two rendering paths, each with a fixed job:
- **(a) `Client` half-blocks**, for everything animated or interactive: the band, the Colony
  diorama, the Board kanban and Squad portraits.
  - Pixels are runs of `▀`: `Text.color` is the top pixel and `Text.backgroundColor` the bottom one,
    both raw `#rrggbb` (`Color = ThemeKey | string`).
  - The frame clock is `surface.every`, and pointer and keys are handled locally.
  - Equal neighbouring cells merge into one run. A `maxRuns` fold coarsens a row rather than
    exceeding the 20,000-node bound.
- **(b) `Raster` from the hooks module, for small non-interactive art in sites the engine
  draws**: the 4x2 globe in `Spinner`, the title-bar logo, and the `/atlas-sprites` sheet.
  It is animated with `$.ui.blit` from `$.clock.every`.
- The band does not depend on `Raster` or blit at all.

**Precedent.** This is the pattern of the shipping `cc-arcade` mod (`github.com/sezaakgun/cc-arcade`):
- `hooks/register.tsx:169-215` mounts `<Client module="./boards/<game>.tsx">` in `AbovePrompt` when
  `e.surface === 'terminal'` and `!e.props.hasSurvey`, sized from `e.viewport.columns` and
  `e.props.maxRows`.
- `hooks/boards/common.tsx` paints with merged colour runs and a `maxRuns` fold.
- `hooks/boards/doom.tsx:126` runs a 20 fps frame clock with `onKey`/`onPointer`, and posts
  scores back through `surface.post`.

**Terminal capabilities on this machine.** The user runs iTerm2, which reports fine pointer
positions. `Image` (true pixels) renders only in kitty and Ghostty and shows its `alt`
elsewhere, so `Image` is a bonus layer and never the primary art. `Svg` with `isInteractive: true`
turns on SMIL animation and CSS `:hover`. The types list `Svg` for Desktop, mobile and VS Code, but
the interface page's table says Desktop only, so stage 0 confirms which. Non-terminal surfaces get
the same scenes as SVG generated from the same sprite grids, and text where `Svg` is missing.

**Motion budget.** Scenes tick at 10 fps while Claude is working or the pane has focus. They
drop to 2 fps when idle and stop while hidden. Ticks come from `surface.every`. A tick, key,
pointer, press or props change between renders resets the render-loop count; three `setState`
calls on consecutive renders with none of those in between unmount the instance. A test drives
the frame clock with `ui.advance` and asserts the instance stays mounted. A `Raster` paints at
most 1,024 colour pairs at once, so sprite palettes stay small.

### 3.1 The band: Contract Track (always on, `AbovePrompt`, a `Client`)

A living strip, not a status string. Three rows, 24-bit colour:

```text
 ⬢ATLAS ░▒▓ research ◆━━━ theory ◆━━━ test ◆━━━ validate ◆━━━▶ ⟦IMPLEMENT 3/5⟧ ┄┄┄ ◇ verify ┄┄┄ ◇ done ▓▒░
   ✦ · ˚  ✧   ·    ˚  ✦     ·   ✧    ·  ˚   ✦ · ▟█▙🌐 ·  ˚    ✧     ·    ✦    ·  ˚     ✧   ·     ✦   62% · 5 left
 ◢ impl-auth ⚒  ◢ verifier-ui 🔍  ◢ docs-cur ✎   ▸ #lead-01a122 ✉2  ▸ ctx ▰▰▰▰▱▱ 41%  ▸ 48k tok · $0.31
```

- **Row 1: the operating contract.**
  - Phase nodes come from `todoPhases` plus `done`.
  - Finished nodes are solid teal diamonds linked by a lit rail. A gradient sweeps along the
    rail when an item completes (a "charge" pulse, 600 ms).
  - The current phase is an inverse-video capsule with its own `n/m`. It breathes at 1 Hz,
    with its glow colour cycling between accent `#2fbd9f` and focus `#7fe0cb`.
  - Remaining phases are hollow diamonds on a dashed rail.
  - `blocked` drains the colour from the whole rail to `#ff7570` and flashes the capsule.
- **Row 2: the titan's walk.**
  - The Atlas titan (section 4) carries the globe along the rail. Its x position is overall
    progress, so it walks toward `done` as items complete.
  - The background is a slow parallax starfield. The density of `✦ ✧ · ˚` rises with the
    session's token throughput (`turn.step` usage), so a busy colony visibly sparkles.
  - When the last item completes, the titan sets the globe down at `done` and a teal
    firework bursts (2 s).
- **Row 3: the squad conveyor.**
  - Each live member is a 4x2 mini-sprite in its persona colour, animated by its state, with
    a name and prop glyph. Then come unread channel mail, the context gauge
    (`$.session.usage().context.percent`), session cost (`usage().cost.usd`), and session
    tokens summed by the mod from `turn.step`/`turn.complete` usage. `usage().context.tokens`
    is only the last response's input, not a session total.
  - Members marked finished slide off the left edge. New spawns beam in from the right
    with a vertical teleport shimmer.
- **Pointer.**
  - Hovering a phase node reveals an absolutely positioned card under it, listing that
    phase's items with owner sprites (`hover` plus `scope`, no hook).
  - Clicking a squad sprite opens the Command Center on that agent's inspector.
  - Clicking the mail glyph opens the Channel tab.
- **Header source.**
  - Phase precedence: (1) the last header in `turn.complete` `e.answer`, matched with
    `headerFirstLinePattern`; (2) the session's first `in_progress` item; (3) `research`.
  - Counts come from the session's todo slice. That slice is filtered once per `todos.json`
    mtime change, never per frame (the live file holds about 1,000 items).
  - The band is right even when a reply forgets its header.
- **Fallbacks.**
  - `maxRows` < 3 collapses to row 1.
  - Non-terminal surfaces draw the same track as an interactive `Svg`, or one line of text
    where `Svg` is missing.

### 3.2 Command Center (`/atlas`, docked sidebar, four full-height tabs)

**Opening.** A pane the user opens is placed at any width. One the mod opens on its own needs
144 columns, or 110 once the user has opened it before.

**Title bar.** An 8-row `Raster` logo animation: the hex-cube assembles face by face, then the
`ATLAS / COMMAND CENTER` wordmark types in. It plays once per session, on first open.

**Tab 1, Colony: a living diorama (`Client`, interactive).**
- **The scene.** A pixel-art orbital station drawn at roughly 2x cell density with
  half-blocks. There is one district per contract phase:
  - Research: an archive with glowing shelves.
  - Theory: an observatory dome.
  - Test: a lab bench with bubbling flasks.
  - Validate: a gate with scanning lasers.
  - Implement: a forge with sparks.
  - Verify: a tribunal with a red-lit scale.
  - Done: a harbour with a docked ship.
- **Live agents.** Every agent is its persona sprite (section 4). It walks along the station
  paths to the district of the todo item it owns, and performs that district's idle loop
  there: hammering at the forge, peering through the telescope.
- **The titan.** The lead titan stands at the hub holding the globe. The globe rotates (8
  frames) and glows brighter with token throughput.
- **Speech bubbles.** When an agent posts to the channel, a pixel speech bubble pops above
  its head with the first 28 characters and fades after 4 s. Notes to `lead` get an amber
  border.
- **Life events.**
  - A spawn is a teleport beam onto the hub pad.
  - Completion is a teal sparkle as the agent walks to the harbour and boards.
  - Failure is a red glitch shake and a grey tombstone tile that stays until dismissed.
  - Stuck (15 min with no note) shows a `z z` loop and a cobweb.
- **Pointer.**
  - Hovering an agent shows a nameplate with persona, `model·effort`, task and last-note age.
  - Clicking it opens an inspector card, an absolute `Box` over the scene with:
    - a 24-tick token sparkline;
    - its last 5 channel lines;
    - the todo item and its evidence;
    - buttons **Steer** (an `Input` that sends a note, or a herdr prompt for an idle pane),
      **Open pane** (a `Link` to herdr-web-ui `http://127.0.0.1:7317/?pane=<id>&chrome=pane`),
      and **Stop run** (destructive; see section 7).
  - Dragging an agent onto another agent opens a pre-addressed message `Input`.
- **Keys.** `←→` cycle agents and `enter` inspects (`surface.onKey`). `Esc` returns focus to
  the prompt.

**Tab 2, Channel: a real IRC client.**
- **Layout.** A nick list on the right, with each nick's sprite avatar, state dot and unread
  count. The message log fills the middle: `12:04 ⚒ impl-auth → lead │ text`.
- **Formatting.** Nick colour is the persona colour. Mentions of `lead` or `human` get an
  amber background stripe. Exit notes render as system lines, `*** impl-auth has quit
  (exit 0, 4m12s)`. Joins and parts come from `channels.json` membership changes.
- **Long and rich notes.** Notes over 3 lines fold with a hover-reveal. Notes containing
  fenced code render as `Code`, and markdown renders as `Markdown`.
- **Typing indicator.** `impl-auth is working…` shows with an animated ellipsis while that
  agent's `turn.step` is in flight. That is live data, not a guess.
- **Composer.** An `Input` with Tab nick completion (`onInput`) and an `@target` prefix parse.
  Enter runs `atlas_todo.py note --owner human --channel C --to X`. A `Select` switches
  channels (main and each lead subchannel).
- **Away from the tab.** A new note to `lead` raises a toast with the sender's sprite, and
  a soft chime if sound is on (`$.audio.play`, off by default).

**Tab 3, Board: a kanban you can drag (`Client`).**
- **Columns.** One column per contract phase, plus Done. Cards show the owner sprite,
  content, age, and an evidence tick when present.
- **Drag a card** with the pointer (down, move, up):
  - to another phase: a phase change (`atlas_todo.py status`, or `add --phase`);
  - onto an agent in the nick strip: claim (`claim --owner`);
  - to Done: an evidence `Input`, then `complete --evidence`.
- **Plumbing.** The `Client` posts each intent through `surface.post`. The hooks module
  validates it and runs the CLI, then hands fresh props back with `{ props }` from
  `ui.message`, so the card snaps into place with no flicker.
- **Column header.** Each header has a mini progress bar. The current phase's column is lit
  to match the band.

**Tab 4, Squad: the persona roster.**
- **Character select.** One card per persona: an animated 16x16 portrait (section 4), with
  role, pinned `model`, `effort`, colour, tools posture, and live count, tokens and cost this
  session.
- **Task-type matrix.** Section 5's table is rendered here. Hovering a task type highlights
  the persona it routes to.
- **Drift panel.**
  - Header misses this session (section 6.7).
  - Effort pins the mod applied to forks.
  - Unpinned spawns that inherited opus, with a cost badge.
  - Frontmatter versus omp mismatches (decision 2).

### 3.3 Restyled built-in sites

- **`Spinner`** is replaced by the titan's 8-frame rotating pixel globe (`Raster`, 4x2),
  followed by the phase capsule and what is actually happening:
  `⟦implement 3/5⟧ impl-auth editing hooks/completion_gate.py · verifier-ui reading 4 files`.
  The "what" comes from `tool.call` events tagged with `e.agentId`.
- **`ToolUse` for `Agent`/`Task` (atlas personas)** becomes a deployment card that keeps the
  engine reference below it.
  - It shows the persona sprite beaming in, a name plate, `model`/`effort` badges, and the
    dispatch name.
  - The card updates live from `$.agent.list()` status: running (sprite animating), waiting,
    completed (green check stamp), failed (red stamp).
  - Hovering it reveals the dispatch GOAL and DELIVERABLE lines.
- **`AssistantMessage`** gets its header line rendered as a coloured phase pill with `n/m`.
  - Hovering the pill reveals the whole contract track as it stood at that reply, so
    scrolling back through the transcript shows the run's progress history.
  - A reply with no header gets a dim `⬢ implement · inferred` pill.
- **`TurnDuration`** becomes a turn receipt:
  `⬢ 4m12s · research → implement · +3 done · 2 agents · 48k tok · $0.31`.
- **`PromptHint`** shows contextual chords: `ctrl+x tab Command Center · /atlas-say @impl-auth …`.
- **`$.prompt.suggest`** offers the next contract step as the dim suggestion after a turn,
  such as `verify: dispatch atlas:verifier on impl-auth`. The user takes it with Tab.
- **Toasts.** A subagent completed or failed (sprite plus verdict), a note to `lead`, a todo completed.
- **Sound pack** (opt-in through `userConfig.sound`): spawn blip, done chime, fail thud,
  phase-advance rising tone. Files ship in `plugins/atlas/mod/fx/` (`$.audio.play({asset})`).

## 4. Pixel characters (one per persona)

**Three resolutions from one source grid per persona** (`mod/sprites/<persona>.ts`, a
palette-letter string grid plus frames):
- **portrait** 16x16 pixels (16x8 cells), for the Squad cards and the inspector;
- **field** 8x12 pixels (8x6 cells), walking in the Colony diorama;
- **mini** 4x4 pixels (4x2 cells), for the band and the nick list.

The same grid emits `Raster` cells, `Client` half-block runs and Desktop `Svg` rects. A
Desktop sprite and a terminal sprite are therefore the same art.

**Shared design language.**
- Every persona wears the atlas hex-cube helmet in its persona colour, with a teal visor
  (`#2fbd9f`) that glints every few seconds.
- Suits are dark (`#121a1e`) with a 1-pixel rim light in the persona colour.
- Each persona has a signature prop and a signature idle animation:

| Persona | Colour (frontmatter) | Prop | Idle loop | Working loop |
| :- | :- | :- | :- | :- |
| lead (main thread) | accent teal and gold | the globe held overhead | globe slowly rotates | globe spins, sparks orbit |
| runner | orange | sneakers, speed lines | bounces on toes | sprints in place, dust puffs |
| explorer | cyan | lantern and folded map | lantern sways | sweeps the lantern, reads the map |
| planner | blue | blueprint scroll | taps chin | unrolls the scroll, draws lines |
| implementer | green | wrench | twirls the wrench | hammers, sparks fly |
| verifier | red | magnifier and shield | polishes the lens | scans, the lens flashes on a hit |
| completeness-critic | red | clipboard | flips pages | ticks boxes, sometimes crosses one out |
| rls-privilege-audit | orange | key ring and padlock | jingles keys | tries keys in the lock |
| db-prober | yellow | drill and DB cylinder | leans on the drill | drills, data bits spray |
| ui-runtime-tester | pink | floating browser window | the window bobs | clicks, the cursor ripples |
| docs-curator | purple | book and quill | the quill bobs | writes, ink trail |
| docs-auditor | orange | book and monocle | adjusts the monocle | skims pages fast |
| schema-inventory | cyan | stacked crates | counts crates | stacks crates |

| armada-<dept> | subagent violet `#b5a3fa` | department badge (2x2 letter) | idle sway | type-on-keyboard loop |
| other / unknown | idle grey `#93a4ac` | none | idle sway | generic work loop |

**States overlay every persona.** Each state has its own animation and FX:
- spawn: a teleport beam;
- working: the persona's loop;
- waiting or input: hand raised with an amber `!` that bounces;
- idle: seated, desaturated;
- done: a teal sparkle and a thumbs-up;
- failed: red glitch frames and `x` eyes;
- stuck: a `z z` bubble;
- killed: fades to a ghost outline.

**Identity.** Two agents with the same persona differ by an accent stripe whose hue is a
stable hash of the dispatch name. Five implementers are therefore distinguishable at a
glance, in both the diorama and the nick list.

**Authoring.** Grids are hand-drawn text art, checked in. `claude plugin test` asserts:
- every `agents/*.md` persona has a sprite in all three sizes;
- every frame fits its box and uses only palette letters;
- every state has at least 2 frames.

## 5. Personas, models and effort by task type

The data comes from `plugins/atlas/agents/*.md` (13 agents; all set `model`, `effort` and `color`).
Enforcement already exists. On Claude, `hooks/dispatch_tripwire.py:586,741-753` denies per-call
`model` overrides on `atlas:*`. On omp, `omp/index.ts:601-637` rewrites an omitted model to the pinned tier.
The policy page is `skills/atlas-orchestrate/references/squad-and-tiers.md`: opus is the
orchestrator only, sonnet is the ceiling for atlas companions, and effort is low except for the
three verdict agents.

| Task type | Persona | Model | Effort (Claude / omp thinking) |
| :- | :- | :- | :- |
| Mechanical edit, exact <=7 STEPS on <=5 files | atlas:runner | haiku (`@atlas-mechanic`) | low / off |
| One bounded implementation | atlas:implementer | sonnet (`@atlas-worker`) | low / **medium** (see decision 2) |
| Explore / map code | atlas:explorer | sonnet | low / off |
| Stage plan | atlas:planner | sonnet | low / low |

## 7. Managed policy and security posture (regulated deployments)

Sources: `plugins/mods/admin.md`, the mods reference, and the settings reference
(`allowManagedHooksOnly`, `disableAllHooks`).

**When the guard loads.** `sec-default@builtin` loads on any machine with managed settings,
and for a user signed in with a Team or Enterprise plan, ahead of every user-installed mod.
If managed `prependPlugins` is set, the guard loads only when that list names it.

**Settings that stop the mod, and what else they stop:**

| Managed setting | Atlas mod | Atlas plugin hooks (`hooks/hooks.json`, 21 command hooks) | Notes |
| :- | :- | :- | :- |
| `allowManagedModsOnly` (set under `pluginConfigs["cc-plugin-sec-default@builtin"]`, managed settings only) | refused unless an org mod | keep running | Status lines and `/goal` keep working |
| `allowManagedHooksOnly` | refused unless an org mod | **blocked**, unless managed `enabledPlugins` force-enables atlas (then hooks run even from a cached install, but the mod still does not load) | Also blocks agent-frontmatter hooks, non-managed statusLine/subagentStatusLine, and `/goal` |
| `disableAllHooks` (managed) | stopped, org mods included | stopped | Built-in mods and Agent SDK hooks keep running |
| `disableSideloadFlags` | the user's `--plugin-dir` is rejected | n/a | The stage 0 spike cannot run on such a machine |
| A site policy mod refusing `process.run` (the admin doc's sample) | refused unless an org mod | n/a | Atlas calls `$.process.run` |

**Fail-open, stated precisely:**
- When only the mod is stopped (`allowManagedModsOnly`, `--safe-mode`, or three hook-worker
  crashes, which unload every mod), the band and the pane are absent. The output-style header,
  LEDGER, the atlas plugin hooks and the dashboard keep working, and nothing in atlas
  depends on the mod.
- Under `allowManagedHooksOnly` without force-enable, or under managed `disableAllHooks`,
  the atlas *plugin hooks* stop too. The completion gate, dispatch tripwire and board capture
  are then all off. Atlas degrades to its output style and CLIs. An admin who wants atlas
  under those settings must install it as an org mod or force-enable it.
- The guard fails closed when it cannot read managed settings.

**Admin path: install atlas as the organisation's mod.** A plugin that Claude Code copies into
its cache from a GitHub, git, URL or npm source counts as the user's, even when managed
`enabledPlugins` turns it on. That includes the current install (cache dir
`tech-tools___atlas___10.4.2`). Such a plugin:
- is skipped by `prependPlugins`/`appendPlugins`;
- is refused by `allowManagedModsOnly`;
- does not load under `allowManagedHooksOnly`.

To count as the organisation's, all three of these must hold:
1. Managed `enabledPlugins` sets `"atlas@tech-tools": true`.
2. Managed `extraKnownMarketplaces` names the marketplace as
   `{"source": "directory", "path": "/opt/<org>/claude-plugins"}`, the absolute path of the
   directory holding `.claude-plugin/marketplace.json`. Device management copies it to the
   same path on every machine. It and every directory above it are writable only by an
   administrator.
3. The marketplace lists atlas by a relative path, so it loads in place. This repo already
   does: `.claude-plugin/marketplace.json:13` has `"source": "./plugins/atlas"`.

Once all three hold, managed `prependPlugins`/`appendPlugins` may order it. A `prependPlugins`
list must name `sec-default@builtin` to keep the guard. `allowModsToOverrideDenyRules` stays
off, because the mod approves nothing. Side effect: the same admin-only update channel then
governs atlas's 21 hooks and all of its scripts, which is the change control an examiner wants.

**What an examiner will ask about** (FTC Safeguards, Reg S-P, GLBA):
- **In-process rewrites.**
  - `agent.spawn`: the mod sets `model` only when it is omitted, and only to the agent file's
    pin. This is ignored for forks, which always inherit.
  - `turn.step`: the mod sets `effort` only for persona-mapped agents.
  - `prompt.submit`: the mod adds one context line per turn (section 6.4) and never changes the
    user's text. An examiner should still read it as a hook that can change prompts.
  - The mod never denies, approves or edits a tool call.
- **Permission boundary.** Deny rules and managed `PreToolUse` hooks do **not** govern a mod's
  own `$.fs`/`$.process` calls, nor the python children it starts. With `Read(.env)` denied,
  those children still run with the user's full access. This is the most important caveat.
  The control is review plus audit: a site policy mod can hook `process.run` by name to log
  or refuse each atlas invocation.
- **Process execution.** The mod runs `python3 <plugin>/scripts/{atlas_todo,atlas_herdr,atlas_mux}.py`
  as the user, with argv only (no shell). Every run is user-initiated, except the 5-second
  `atlas_herdr.py status` poll. That poll is read-only per its docstring (`atlas_herdr.py:836-889`):
  `ps`, two herdr socket pings (`:335`, `:857`), a possible `herdr --version` subprocess
  (`:555-563`), and health probes on several loopback ports (`:794-829`).
- **State-changing actions**, all user-initiated, each listed in `docs/atlas-mod.md`:
  - todo add, claim, status and complete, and channel notes (`atlas_todo.py`);
  - **steer**: a herdr prompt into an idle pane. This needs a **new** `atlas_herdr.py prompt
    --pane --text` subcommand, because the CLI today exposes only status, ensure, reap,
    install-check and create-pane (`atlas_herdr.py:1125-1137`). It wraps the existing
    `send_prompt` (`:308`).
  - **Stop run (destructive)**: `atlas_mux.py kill --run R` takes only `--run`/`--root`
    (`:854-857`). On herdr it closes the whole run workspace and every pane in it
    (`atlas_herdr.py:731-738`). On tmux it is `kill-session`, which also kills the lead window
    (`atlas_mux.py:788-789`).
    - The confirmation (`$.ui.ask`) lists every worker that will die.
    - `exit 137` is written only for a worker that posted no exit within 2 s
      (`atlas_mux.py:734-754`).
    - A per-agent **close pane** needs a second new subcommand, `atlas_herdr.py close-pane --pane`.
      Until it exists, the inspector offers only Stop run.
- **File access.** The mod reads `<root>/.atlas/.run/`, the plugin's `agents/`, `contracts/`
  and `mod/fx/`, and nothing else. Writes happen only inside the CLIs above.
- **Network.** The mod makes no `$.http` calls, and its links point only at localhost. Python
  children do their own I/O outside the mods API, so a policy mod hooking `http.fetch` does
  not cover them.
- **Proof for review.** `claude plugin validate --json plugins/atlas` prints the exact `hooks:`
  and `calls:` surface. `docs/atlas-mod.md` ships that output.

## Assumptions vs proven

Proven from docs and the generated 2.1.293 types:
- `turn.step` carries `agentId` (pinned) and a rewritable `effort`
  (`'low'|'medium'|'high'|'xhigh'|'max'|number`) (`TurnStepInput`).
- `agent.spawn` input: `tool_use_id`, `prompt`, `description`, `subagentType` (resolved;
  `fork` for forks), `provider`, and `model?`. A hook sets `model` to pick the subagent's
  model. It is "ignored for forks, which always inherit" (`AgentSpawnInput`).
- `Text.color`/`backgroundColor` take a theme key or a raw colour string
  (`Color = ThemeKey | string`).
- `Client`:
  - it gets a frame clock (`every`), local state, `onPointer` (sub-cell `fine` x/y on iTerm2,
    kitty, Ghostty, WezTerm and foot; none through tmux) and `onKey`, plus `post` → `ui.message`;
  - it cannot contain `Raster`/`Image`;
  - three `setState` calls on consecutive renders, with no key, pointer, tick, press or props in
    between, unmount it (`ClientSurface`).
- `Image` shows true pixels only in kitty and Ghostty, and its `alt` elsewhere (`ImageProps`). On
  this machine (iTerm2), sprites must use half-blocks.
- `Raster` and `Image` are terminal-only. `Raster` paints at most 1,024 colour pairs at once.
- `Svg` animates and hovers with `isInteractive: true`. Which surfaces get it is unresolved: the
  types list Desktop, mobile and VS Code; the interface page says Desktop only.
- Redraw is 10/s, or 30/s for the visible terminal pane/band.
- Hook modules get no Node APIs or timer globals.
- `claude -p` runs mod hooks without drawing.

To prove in stage 0 (runtime):
- `e.agentId` on `turn.step` matches `$.agent.list()` ids, and the effort rewrite takes effect on a
  subagent's request.
- The atlas band's 10 fps half-block scene stays smooth in iTerm2 and inside a herdr pane. A
  `Client` in `AbovePrompt` on the terminal is already shown to work by `cc-arcade` (20 fps).
- `Raster` renders in herdr panes (tmux passes no `fine` pointer, so the diorama degrades to cell
  precision there).
- The hooks module can import sibling files (`./data.ts`), or it must be one bundled file.
- `modules` in the atlas `hooks.json` coexists with the existing plugin hooks, and older
  Claude Code versions ignore the key.
- `prompt.submit` `next({...e, context})` reaches the model on every turn without busting the prompt cache prefix.
- `.atlas` root resolution in linked worktrees matches what `atlas_todo.py` writes.
