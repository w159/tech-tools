# Atlas 16.7.0: warm lead benchmark

Date: 2026-10-29. Question: does the crew reach a quarter of the wall time of
one Claude prompt when the lead is already running when the task arrives?

Answer: yes at 8, 18 and 30 modules against the single prompt measured the same
day (22.4%, 17.4%, 19.1%). Against the 16.4.0 single-prompt baseline from
2026-10-28 the 8-module cell is 26.2% (1.8 s over); see "Baseline drift".
Tokens are 11.9-13.8% of the single prompt. Every number below is measured.

## Timing rules

Jerry changed the timing rule twice on 2026-10-29:

- 11:51 UTC: allow a warm lead. The crew's lead is started and idle before the
  task arrives; team time runs from hand-off to the lead's result. The single
  prompt keeps the old timing (process start to exit).
- 12:00 UTC (relayed from his main chat): also report start and exit excluded
  on both sides.

Three columns per size:

1. Cold: both arms timed from process start to exit (the rule up to 16.6.0).
2. Warm lead: crew from hand-off to result, single prompt cold.
3. Start/exit excluded: both arms from hand-off to the last result. The single
   prompt runs in the same stream-json input mode and gets the task when its
   start-up is done. When the single prompt starts background agents the CLI
   emits more than one result; the time runs to the last one.

## Method

- Model `claude-sonnet-5-5`, effort `medium`, lead and every worker, both arms.
- Fixtures: 8 modules (213 tests), 18 modules (469 tests), 30 modules (784 tests).
- Median of 3 runs per cell. Every run passed every test (pytest rc 0, 0 failed).
- All arms rerun the same day, one at a time, on 4 shared CPUs.
- Crew code: wip/warm-lead 7701ad65 (released as 16.7.0) for the warm runs;
  16.6.0 for the cold crew runs (the crew itself did not change).
- The warm lead idles 5 s after it reports ready, then `atlas_warm_lead.py send
  --wait` hands it the `/atlas:atlas-crew` task; the time is measured around
  that call.

## Baseline drift

The single prompt was slower on 2026-10-29 than in the 16.4.0 baseline
(144.1 / 181.2 / 227.8 s). Against that older baseline the warm crew is
26.2% / 21.7% / 19.3%, so 8 modules misses by 1.8 s. The single-prompt arm
varies a lot between runs (18 modules cold: 190.1 to 417.4 s), which is also why
the start/exit-excluded single prompt can come out slower than the cold one:
they are different runs.

## What a warm lead costs while idle

Measured on a lead with the Atlas plugin, idle for 120 s after ready:

- Memory: about 250 MB for the lead plus 4 child processes of about 89 MB each,
  about 600 MB in total.
- CPU: 0.75 CPU-seconds in 120 s.
- Tokens: none. The lead printed no output while idle, so it made no model call.
- With recycle on (the default), a fresh lead starts after each task, so one
  lead is always idle and ready.

## What changed since 16.6.0

- `atlas_warm_lead.py` (start, send, status, stop): a tmux-hosted lead in
  stream-json input mode, task inbox on a FIFO, state in
  `.atlas/.run/warm/<name>/`. `send --wait` returns at the lead's last result
  once no background agent it started is still open.
- The crew, planner and worker prompts are unchanged.
