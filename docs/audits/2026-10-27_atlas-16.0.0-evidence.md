# Atlas 16.0.0 before/after evidence

Date: 2026-10-27. BEFORE is main at 9c20c37 (atlas 15.2.1), checked out as a detached worktree. AFTER is branch `claude/project-thread-9eezyd` at 1b9e2d5 (atlas 16.0.0, armada 2.0.0). Each measurement ran the same command in both trees, as root, in a scratch project or git repo, with a fresh `session_id` per hook run.

Verdict: every fix shows a measured gain on the AFTER tree. One regression appeared during measurement (a false doctor warning) and was fixed in 1b9e2d5 before this file was written. No test that passes on BEFORE fails on AFTER.

## Regression found and fixed

The dispatcher port moved the tripwire's PostToolUse binding into `event_dispatch.py`. `atlas_doctor.check_orchestration_wiring` still looked for `dispatch_tripwire.py` in hooks.json, so every SessionStart on a dev tree printed "atlas plugin is unhealthy ... PostToolUse matcher missing Agent / Task / Skill". Commit 1b9e2d5 makes the check accept either layout and reads the tripwire matcher from `event_dispatch.BINDINGS`. Three new tests failed first, then passed; the doctor suite runs 146 OK and the hook output is empty.

## Caveats

- Fix 3: when `docs/` exists and no agent was dispatched, BEFORE already blocks on (m). AFTER blocks on (m) plus (a)(b)(f)(k)(o), a heavier block for the same case.
- The live tmux run is one team per tree (n=1 each).
- Stop hook timing: 147 ms BEFORE, 158 ms AFTER, within run-to-run noise.
- falcon was not launched in either tree (no venv; `uv run` would install packages). Its cost is the same in both.
- The tmux workers load agents and hooks from the installed plugin via `--agent atlas:<role>`. What differs between trees in that run is `atlas_mux.py`, `atlas_panefeed.py` and `--allowedTools`.
- Connector savings apply only to sessions that install atlas without armada.
