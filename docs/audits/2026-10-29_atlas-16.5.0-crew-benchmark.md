# Atlas 16.5.0: crew benchmark

Date: 2026-10-29. Question: after 16.4.1 (29-33% of the single prompt's wall
time), does the crew reach a quarter of the wall time of one Claude prompt, on
the same tasks and model?

Answer: at 30 modules yes, by a hair: 56.5 s against a 57.0 s target (24.8%).
At 18 modules (26.4%, 2.5 s over) and 8 modules (28.2%, 4.6 s over) not yet.
Tokens are 11.9-16.9% of the single prompt (target 50%: met). Numbers below are
measured, not rounded.

## Method

Same harness, fixtures and single-arm baselines as the
[16.4.0 page](2026-10-28_atlas-16.4.0-crew-benchmark.md).

- Model `claude-sonnet-5-5`, effort `medium`, for the lead and every worker, in
  both arms.
- Three fixtures, each a Python package set with a SPEC.md, stub modules and a
  test suite: 8 modules (`pkgkit`, 213 tests), 18 modules (`pkgkit` + `mdkit`,
  469 tests), 30 modules (`pkgkit` + `mdkit` + `cronkit`, 784 tests).
- Crew arm: `claude -p "/atlas:atlas-crew --spec SPEC.md --files '<glob>' --tests '<pattern>' --check 'python3 -m pytest -q' --model claude-sonnet-5-5 --effort medium" --plugin-dir <repo>/plugins/atlas`.
- Wall time: process start to process exit, measured outside the process, so it
  includes the full start and exit of the lead. Each cell is the median of 3 runs.
- Tokens: input + cache writes + cache reads + output summed over the lead and
  every worker, as in the 16.4.0 page.
- Every run passed every test; nothing under `tests/` changed except
  `__pycache__` files.
- Container: 4 CPUs shared by every worker.

Single-arm medians (copied from the 16.4.0 page, not rerun):

## What changed since 16.4.1

- v11, launch priority: workers start least slack first (`launch_order`), with
  nice tiers by rank (`min(19, 4 * (rank // ncpu))`). 30 workers started at once
  on 4 CPUs had median init 10.6 s and first result 19.4 s (alone: 0.7 s, 4.1 s).
- v11, stage dir: workers Write to `.atlas/tmp/<run>/<nick>/` and `irc check`
  installs the files. Bash heredocs were refused by the shell safety check, at
  10-25 s lost per refused write.
- v11, the supervisor starts the final check while workers are still exiting.
- v12: the final check is sharded across CPUs; one docstring-restore pass per
  check instead of a second unit-check run.
- v13: DONE records an owned-files sha256 digest and hooks skip the re-check when
  the DONE is current. One 30-module run lost about 17 s when the early-exit
  re-check hit the 10 s PostToolUse timeout under load.
- v14, weights: generation weight is spec section chars only, at 400 chars/s.
  Basis: 162 worker runs, API time correlates 0.78-0.84 with spec chars and
  -0.18 to -0.28 with owned stub chars; residual sd 3.75 s.
- v14, stagger: a worker that would only wait on peers starts `min(8, wait - 7.5)` s
  later.
- v14, speculative check: `irc check` runs as soon as every peer file is
  installed and posts DONE without a re-run when the peers' DONE digests match.
  At 8 modules all DONEs landed within 0.6 s of the critical file's DONE (was 2.5 s).
- v15: DONE records `peer_digests`; the supervisor's final check skips test files
  a worker already passed on the same bytes. The full re-run cost 1.7-4.4 s after
  the last DONE at 30 modules. Unowned tests still run.

Off switches: `ATLAS_CREW_PRIORITY`, `ATLAS_CREW_STAGGER`, `ATLAS_CREW_SPECULATE`,
`ATLAS_CREW_CHECK_CACHE` (each `=off`).

## Where the remaining time goes

Measured in the v15 runs.

- Lead process boot and exit: 5.6-7.3 s.
- Lead reply after the crew: 4.3-6.3 s. Time to first token is 1.5-2.2 s on about
  28k new input tokens; the rest is the harness's post-turn work and Stop hooks.
  Atlas lead hooks measured 0.12-0.51 s each.
- Crew start: 0.2-0.9 s.
- 8 modules: `ranges.py` is one API call of 22-24.6 s (3.8-4.3k output tokens) on
  the critical path. Lead overhead (about 11-13 s) plus that call already reach
  34-37 s against the 36.0 s target, so little room is left; the rest of the gap
  was not attributed.
- 18 and 30 modules: the spread is model rework. `mdkit/cli.py` failed the same
  test on its first check in 4 of 6 runs (option `--min 7` must be "invalid
  value", SPEC.md lines 1287-1290), costing 3.4-3.8 s each. The 66.3 s run also
  reworked `cronkit-cli` and `pkgkit-cli`.
