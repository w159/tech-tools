The figures in the "Evidence" lines were re-run by the lead after the fixes.

## B. Defects

Each row: finding, which model, what was done, evidence. Evidence commands run from the repo root.

1. **Gate (b) spoofable (both).** `atlas_finding.py` sets `stamped_by` to `ATLAS_WORKER_NAME` or `lead`; `--by` is free text; the gate accepted any `--by` different from `stamped_by`. Done: a verified finding is credited only with a hook-written record for this session and run: an `atlas:verifier` or `atlas:completeness-critic` dispatch row with `ts` at most `verified_at` + 1 s and a role matching `verified_by`, or a team or crew member record (verifier or completeness-critic role) whose name equals `stamped_by`. A bare `--by atlas:verifier` no longer credits, and the block text no longer suggests `--by`. Evidence: 11 failing-first tests, `FindingsIdentityBackingTest` in `hooks/test_completion_gate.py`. Residual limits: an in-process verifier still stamps as `lead`, so credit depends on the dispatch row; a lead can pair a real verifier dispatch with a self-stamped row; `ATLAS_WORKER_NAME` can be set by the process environment; an unreadable DB fails open with a stderr line.
2. **Gate (b) test-command credit was a substring match (both).** `pytest -q --collect-only` satisfied a reproduction of `pytest -q`. Done: exact canonical match, with whitespace collapsed and leading `cd X &&` and env assignments stripped. Evidence: same test class.
3. **The cross-check missed the commonest fabrications (both).** "42 passed" after only `ls` raised no finding; "0 failed" counted as a hedge (`\bfailed\b`) and skipped the pass-after-failing-run check; any digit in any output excused a count (Read line numbers); the word "push" or "CI" anywhere counted as evidence; two identical branches at `done_claim.py:282-288`; a stale "shadow" comment at `:33-34`. Done: "0 failed" and "no failures" no longer hedge or skip; counts are checked only against test-run output of the turn; push needs a `git push` command with ref-update output (also accepted: a compound command with ref-update output, or `git ls-remote` with output); CI needs a `gh run`, `gh api`, `gh workflow`, `gh pr checks|view|status` call or a CI tool; the dead branch and the stale comment were removed. Evidence: `python3 plugins/atlas/hooks/done_claim.py --eval`, all-rows blocking path n=182 TP 32 FP 0 FN 12 (precision 1.000, recall 0.727); before the fixes TP 30 FP 0 FN 14.
4. **The eval did not test the production path (Opus).** 179 of 182 rows carried a synthetic `_all` record that added session-wide numbers to the evidence pool. Done: the eval no longer feeds `_all` into evidence.
5. **The seeded corpus is circular and leaks across splits (both).** About 8 templates repeated with random numbers; dc-133 (test) and dc-134 (dev) share a transcript and a fabricated count. Done: the corpus was re-split by source transcript and seed template (`--resplit`, 57 groups, 109 dev rows, 73 test rows, no group in both; tested). Not done: the seeds are still built from the detector's own rule kinds, so seeded recall measures coverage of those kinds. Added to ROADMAP: more real unsupported-claim rows.
6. **A new finding kind was not precise enough to block.** An intermediate untiered version had 2 false positives on real rows (dc-084 and dc-092: relayed counts with no test run this turn). Done: finding kinds are tiered. `BLOCKING_KINDS` are those with dev-split precision of 0.95 or better (`count_not_in_results`, `pass_after_failing_run`, `narrow_as_full_suite`, `push_unbacked`, `ci_unbacked`); `count_no_test_run` (dev 8/9 = 0.889) is an advisory, recorded as `decision.verify.block-would` in `auto` and blocking only with `ATLAS_DONE_CLAIM=block`. The gate's block mode uses `done_claim.blocking_findings`. Evidence: the per-kind table printed by `--eval`; real rows blocking path n=131 TP 1 FP 0 FN 2 (precision 1.000, recall 0.333); seeded n=51 TP 31 FP 0 FN 10. Only 3 real unsupported claims exist in the corpus, so real-world recall is measured on n=3, and the labels are model labels (kappa 0.767). The test-split label metrics are precision 0.889, recall 1.000 (n=73). Latency: `analyze()` p95 1.40 ms, added hook latency p95 2.26 ms.
7. **Isolation bench was by construction (both).** The shared baseline was whole-file last-write-wins, so every same-file case lost an edit (8 same-file diff-hunk plus 6 same-line is exactly 14 of 20), which Claude Code's Edit tool does not do; "0 lost" counted a kept conflicting branch as not lost; the bench never ran `spawn-team`. Done: the bench models Edit semantics for the shared tree (exact `old_string` against current content, refused if stale or missing). Evidence, per edit, 40 edits over 20 cases: naive overwrite (upper bound) 26 merged, 14 lost; shared (Edit semantics) 26 merged, 14 refused for retry, 0 lost; worktree 34 merged, 6 conflicted (kept branch, unmerged), 0 lost; auto chose shared for the 6 disjoint cases and worktree for the 14 same-file cases, with the same outcome as worktree. The claim is now that worktrees avoid 14 retries and leave 6 same-line conflicts on kept branches for the lead. It is still a simulation, not `spawn-team` with real workers.
8. **The history bench could leak the answer (Opus).** The Atlas arm loaded the plugin from the working tree, where every task's fix already exists. Done: the arm loads `plugins/atlas` exported from each task's parent commit (`git archive`). Evidence: validate mode passes for all 8 tasks. The 48 paid runs still have not run.
9. **The verifier rule was tuned on its own test (both).** The rule names count, command, test file and mismatch, matching the false-claim cases that motivated it; the 3/18 to 17-18/18 lift is on 6 cases; no good case had a harmless claim difference; the harness dropped the seat's ToolSearch and findings sections. Done: 20 held-out cases written after freezing `agents/verifier.md` (hash `9d41bcc904f488e7c553c80c45703e462791f044`, unchanged), run with the shipped seat prompt (MCP off in the sandbox), sonnet, 3 trials, USD 1.32. Evidence (`2026-11-15_atlas-verifier-seeded-eval.md`, held-out section): false-claim catch 30/30 runs (Wilson 88.6% to 100%) and 10/10 cases (72.2% to 100%) over 10 mismatch kinds the rule does not name; false refutes on harmless divergence 2/30 runs (1.8% to 21.3%), both on the ambiguous `absolute_path` case, 0/27 excluding it. Only sonnet was run.
10. **The regression test is a snapshot (Opus).** It pinned exact counts. Not changed beyond the new thresholds: it fails when test-split label precision or recall falls 0.02 below `SHIPPED_TEST_PRECISION` and `SHIPPED_TEST_RECALL`.
11. **CHANGELOG 17.24.0 contradicted itself (both).** One bullet said the default was `shadow` (real-row precision 0.500), another said `auto`; "### Added" appeared twice. Done: the shipped default is `auto`, which blocks only on `BLOCKING_KINDS` findings; the headings are merged. Evidence: `plugins/atlas/CHANGELOG.md` 17.24.0 entry.
12. **README table row broken (Sonnet).** `auto|ollama|systemone` inside a table cell split the row. Done: the pipes are escaped.
