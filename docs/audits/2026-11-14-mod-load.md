# Atlas mod load failure, 17.19.0 to 17.21.0 (fixed in 17.21.1)

## Symptom

In Atlas 17.19.0, 17.20.0 and 17.21.0 no mod surface drew: no band, no TODO block, no SUBAGENTS block, no side panel. Claude Code printed one startup line and loaded none of the Atlas hooks module.

## Cause

`mod/usage.ts`, added in 17.19.0 (c35b5887), broke two rules the Claude Code host applies when it loads a mod:

- `mod/usage.ts:39-40` (before): `return $.env.get(name).catch(...)`. The host lists the variables a module reads, so the first argument of `$.env.get` must be a quoted literal at every call site. A variable name is refused.
- `mod/usage.ts:136` (before): `if (typeof $.clock.after !== 'function')`. A `$` member must be called where it is spelled (`$.noun.event(...)`); reading it as a value is refused.

The host stops at the first violation and drops the whole module.

## Loader messages

```
atlas: hooks module did not load: .../mod/usage.ts, compiled line 26 `return $.env.get(name).catch(() => {`:
$.env.get takes a literal name as its first argument, so the variables a module reads and writes can be listed (got the variable name)
```

After the first fix the host reported the second rule:

```
.../mod/usage.ts, compiled line 181 `if (typeof $.clock.after !== "function") {`:
$.clock.after is used as a value (an event of $ bound, passed or read) instead of called
```

## Fix

- 164c4b67: `envGet` takes a closed `EnvName` union and a `switch` that spells each variable as a literal `$.env.get('NAME')` call.
- ba9f66c2: the `typeof $.clock.after` fallback is removed; `$.clock.after(...)` is only called.
- `mod/host-load-rules.test.ts` gained rule 5 (literal first argument on `$.env.get`, 164c4b67) and rule 6 (every `$.noun.event` member is called where it is spelled, ba9f66c2). Both scan every mod and omp source file, so another file cannot reintroduce either.
- 17.21.1 also fixes the nine `tsc -p mod/tsconfig.json` errors in three test files (`Bun`, `setTimeout`, a `'dark'` theme literal). Test typing only.
