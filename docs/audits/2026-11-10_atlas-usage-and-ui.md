Ask: check the usage reports, find where meaningful improvements can be made, and improve the
terminal UI and the mods/widgets on Claude Code and omp with display parity.

## 2. Measured evidence used instead

- A live Claude Code session (v2.1.321, 150x45 tmux pane, `--plugin-dir plugins/atlas`, a two-line
  Python task in a scratch dir). It used 18,530 output tokens. One completion-gate block caused about
  5 extra calls (about 3k output tokens, about 360k cache-read tokens, about 41 s) spent recording
  phases that never ran and a finding labelled `atlas:verifier` that the lead wrote itself.
- A replay of every tool call from that transcript through `hooks/hooks.json`, run with a fresh
  `HOME`, `TMPDIR` and session id on each side (old tree from `7fa2f6bb`, new tree from this change).
- `atlas_gates.py --json` for that session, and `atlas_doctor.py` in this repo.
- Fixed-width renders of the band, the omp mission panel and the sidebar route view from the shared
  fixtures.

## 3. Ranked findings and what changed

Ranked by cost observed in the live run.

| # | Finding (evidence) | Change |
|---|---|---|
| 1 | The (o) hint told the model to scaffold six phases; it then marked research to validate complete for a two-line task (live run). | Hint names only the missing phases (`scaffold --phases implement,verify`) and says never to tick a phase to satisfy the check. |
| 2 | `atlas_finding.py --by` defaulted to `atlas:verifier`, so the lead's own check was recorded as an independent verdict (live run). This undercuts the adversarial check. | `verified_by` is the caller: `--by`, else `$ATLAS_WORKER_NAME`, else `lead`. Verifier prompts pass `--by atlas:verifier`. |
| 3 | The output style's example `LEDGER \| 3/5` line is stored in the transcript as an `output_style_instructions` attachment. The gate read it as the run's ledger: 2 phantom open todos for (i), and a satisfied (k) with no plan. | Ledger lines are read only from assistant messages or plain text lines. |
| 4 | Gates view counted 5 native Bash calls as routing misses in a project with no lean-ctx, where native tools are the only route; the sidebar showed `g: core ✗4`. | Native tool lines pass when lean-ctx is not configured; the detail says so. |
| 5 | Band rail at 92 columns dropped to marks only (`✓ ▶ ✓ ▶ ✓ ▶ IMPLEMENT ▶ · ▶ ·`) although the full rail fits. omp already kept names. | Band and omp panel both try full, then 3-letter, then marks, against shared goldens. |
| 6 | Sidebar rail was glyph-only below 80 columns and misaligned (`☰○○`, `⚒○─`); `done` showed every phase hollow; an empty phase said `nothing planned` while other phases had work. | Rail keeps the current phase named; `done` ticks all; empty phase points at open work or says `all N done`. |
| 7 | A busy turn sent one toast per change and flooded the host notice area. | One merged toast per turn, capped at 100 characters. |
| 8 | Doctor printed 36 lines, mostly PASS and not-applicable rows, with no verdict. | FAIL, WARN, PASS order; one SKIP line; verdict line with counts; `--verbose` for all rows. 27 lines here. |
| 9 | `env \| grep PATH` was flagged as a full env dump. | Filtered env is allowed unless the filter is inverted, empty, `\|\|`, or names a secret word. |

## 5. Regression checks

- Hook replay of the live transcript, fresh state per side: the completion gate blocks only on (p)
  on both trees (1935 vs 1813 bytes; the gap is the longer plugin path on the old tree). Total injected
  bytes 4537 vs 4101. Per-hook timings are within noise (event_dispatch about 60 to 90 ms each side).
- An earlier replay that reused one session id showed 5449 vs 0 bytes. That was a once-per-session
  marker left by the first run, not a product change; the rerun above replaces it.
- Crew, IRC and mux code are untouched, so the benchmark harness and its token and time numbers do
  not move.

## 6. Tests

Each new test was run against the old source (`7fa2f6bb`) with only the test files copied in:

- pytest: 9 new tests fail on the old code (style-attachment ledger as open work and as a plan, (o)
  hint, writer default, verifier prompts, no-lean-ctx routing, filtered env, two doctor render tests).
  `test_assistant_ledger_still_counts_in_json_transcript` passes on both, as a guard.
- bun: `mod/band-golden.test.ts` and `mod/notify.test.ts` fail to load on the old code (`railRow` and
  `mergeToasts` did not exist); the omp 40-column rail tier and three sidebar route cases fail on
  assertions. The omp 92 and 56 column tiers pass on both, which is the parity gap this change closed
  on the Claude Code side.
