# Atlas 17.18.0: crew time, the seal and Ctrl-C

Date: 2026-11-14. Base: atlas 17.17.1 plus the uncommitted 17.18.0 tree. All runs: claude-sonnet-5-5, effort
medium, the same model for lead, workers and the plain baseline. Harness: `/home/user/bench/arm.sh`. Cold
includes CLI start and exit; warm uses a started lead, so start is excluded. Companion to
[2026-11-14_atlas-17.17.0-silent-failures.md](2026-11-14_atlas-17.17.0-silent-failures.md).

## Where the time goes (17.17.1)

- Profile, 8 modules (fixture-p): cold 31.6 s, warm 28.2 and 27.8 s, 159k tokens; plain one prompt 55.7 s, 365k.
  The crew engine was about 15 s of that. The slowest worker (money) alone took 14.2 s: 2,074 output tokens,
  661 of them thinking.
- Thinking cannot be turned off: Claude Code 2.1.325 on this model keeps thinking with
  `CLAUDE_CODE_DISABLE_THINKING=1` and `MAX_THINKING_TOKENS=0` (254-390 thinking tokens per probe run).
- Trials that did not help (n=1 cold, 2 warm each): worker effort low (noise); the check moved to the worker Stop
  hook (worse, crew 23.7 s); thinking off (no effect); an early DONE from a PostToolUse Write hook (the model's
  next Bash turn was already requested, no gain); a router prestart of the crew (no time gain, tokens 71% of
  plain). None shipped.
- Lead overhead outside the crew on 16 modules was about 14.4 s: start and turn 1 6.3 s, pre-engine 2.3 s (it
  grew 1.1 s from 8 to 16 modules: `green_check_guard`), turn 2 2.5 s, Claude Code post-turn 3.0 s, return poll
  0.3 s.

## What shipped for speed

- Router asks for a final reply of at most 3 lines after a green crew (`hooks/prompt_optimizer_core.py`).
- `green_check_guard` runs plain pytest unit checks in min(cpus, files) shared interpreters
  (`scripts/atlas_crew.py`): 16 modules 1.23-1.52 s to 0.42-0.48 s.
- Engine polls 0.05 s instead of 0.5 s and 2 s (`POLL_S`): fake 16-worker run 3.08 s to 1.67 s mean.
- An empty rest shard is not spawned: 0.26 s to 0.001 s.
- Stop hooks measured fast (completion_gate 130 ms, stop_tail 45-68 ms), so they were left alone.
- The faster poll made the lead see "money: 143" for a worker the supervisor had stopped after its verified DONE
  and spend a third turn re-verifying (+50k tokens). Such a worker is now marked `stopped_after_done`, is not a
  late exit, and its turns and tokens are counted from the stream when no result event exists.

## Goals

- 50% of the plain prompt's tokens: met at 8 and 16 modules, cold and warm.
- 1/4 of the plain prompt's wall time: NOT met. 28-29% at 16 modules, 47-48% at 8. The floor is the slowest
  single worker's own model time (about 14 s for money) plus about 11 s of lead time, which is two model turns
  and Claude Code's own start and post-turn work. Crew time stayed flat from 8 to 16 modules while plain time
  grew, so the ratio falls as tasks grow. That is a trend from two sizes, not a measured 1/4.

## Behavior changes

- Ctrl-C: 17.17.0 put each worker claude in its own session, which cut off the pane's Ctrl-C. It now starts in
  its own process group (`process_group=0`, or `os.setpgrp` before Python 3.11) and `tcsetpgrp` makes it the
  pane's foreground group; the terminal is handed back after exit. A SIGTERM and SIGHUP handler installed before
  `Popen` kills the group, so a kill before the pid-file write leaves no claude running.
- Seal (`scripts/atlas_crew_seal.py`): summaries are HMAC-SHA256 signed with a per-run key in
  `$ATLAS_HOME/crew-seals` (0600, directory 0700). `run.json` stores the seal home. Records are pruned when the
  run dir is gone or after 14 days. `wait` and `run --wait` refuse an unsealed or edited summary; `run --wait`
  returns at once with `no seal record under <home>`. A run id cannot be reused.
- Stop gate (`hooks/gate_rerun.py`): credit needs the transcript to show this plugin's own `atlas_crew.py run`
  printing that run id (a `wait` alone, a `python -c` or a copied script earns nothing) and a verified seal. A
  killed run is no longer an engine-verified red. Limit: code running as the same user can read the key record or
  call `create` and `sign` and so forge a seal. The seal catches edited or copied summaries; the launch check
  catches forged run dirs.
- IRC: after a fix message a worker can re-post DONE even when its files did not change. Mux: kill exit notes use
  the spawn time, so an earlier run's exit note no longer suppresses one.

## Adversarial pass

A separate critic model (claude-opus-5-5, high effort) and an `atlas:verifier` attacked the 49 fixes of 17.17.0
and 17.17.1 and the new work.

- Reproduced and fixed: seal forgeable through its public create and sign (now the launch check); a killed run
  counted as red; `run --wait` spinning when the seal record could not be written; `ATLAS_HOME` mismatch dropping
  credit; seal records never pruned; a kill before the pid file leaving claude; run id reuse; a fix-round DONE
  not re-posted; mux kill notes ignoring spawn time.
- Overstated and corrected: 5 tests added in 17.17.0 pass on 17.16.0 code too
  (`test_a_fix_round_wait_ignores_a_stale_round_0_done`, `test_a_live_wrapper_is_not_declared_dead`,
  `test_a_current_done_does_not_rerun_the_unit_check`, `test_unowned_helpers_that_reach_no_peer_keep_the_cache`,
  and the contract-header test at top level). They are regression guards, not proof of those fixes. The 17.17.0
  red-fixture benchmark (86.3 s against 71.6 s) was n=1 per arm.
- Confirmed: the other 17.17.0 tests fail on 17.16.0 code and pass after (2735 passed on the changed test files).
- Not reproduced: the critic's claims about stty tostop, a green verdict flipping red after publish, and a run id
  missing from argv.
