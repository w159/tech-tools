# Atlas 17.17.0: silent failures and slowdowns after 17.16.0

Date: 2026-11-14. Base: main e0673ace (atlas-v17.16.0). Scope: the crew, IRC, tmux (mux), worker hooks, the Stop
gate, the session hooks, the doctor, the CLIs and the command examples in the docs. Each finding below was
reproduced first, then fixed, with a test. An adversarial verifier (a fresh `atlas:verifier` with no part in
the fix) then tried to refute each fix, using the real hook entry points with JSON on stdin, real
`atlas_crew.py` runs with a fake `claude`, and real Claude Code transcripts. A refuted fix went back for
another round. The rounds are listed under "Adversarial review".

## Benchmark

Two runs per cell. The 17.16.0 and 17.17.0 arms alternated in one session on the same machine. Every run ended
with 434 passed. A third lead turn is marked with its cause.

| Run | 17.16.0 wall | 17.17.0 wall | 17.16.0 tokens | 17.17.0 tokens |
| --- | --- | --- | --- | --- |
| fixture-p cold | 29.2, 30.9 s | 27.2, 27.7 s | 158,137, 158,807 | 157,745, 157,849 |
| fixture-8b cold | 31.3, 34.0 s | 29.9, 28.3 s | 158,339, 210,915 (gate block on header order) | 210,461 (lead chose an extra `git status`), 157,638 |
| fixture-p warm | 27.8, 28.6 s | 26.3, 25.4 s | 158,570, 158,409 | 210,733 (lead chose an extra `git status`), 158,549 |
| fixture-red cold (one worker's test fails) | 86.3 s, 5 lead turns | 71.6 s, 3 lead turns | 725,395 | 614,383 |

- On the green fixtures 17.17.0 is 1 to 3 s faster per run, the parallel green-check guard plus a summary that
  no longer waits on DONE workers. That is within the run-to-run spread, so treat it as no regression rather
  than a speedup.
- Tokens are the same except for extra lead turns. 17.16.0's came from the gate blocking a header written
  phase-first (fixed below, finding 47). 17.17.0's came from the lead choosing to run `git status`.
- On the red fixture the blocked-report fix saves two lead turns: 17% wall time and 15% tokens.
- Against one plain prompt on fixture-p (51.7 and 55.7 s, 307,662 and 364,959 tokens), 17.17.0 cold is 51% of
  the wall time and 47% of the tokens. Warm it is 48% of the wall time.
- 1/4 of the wall time is still not met.

Method: the 17.16.0 harness. Same 8-module fixtures and prompts, claude-sonnet-5-5 at effort medium,
`claude -p --permission-mode acceptEdits --allowedTools Bash --setting-sources project,local --plugin-dir <snapshot>`.
Arms alternated run by run. Cold is process start to exit. Warm is a lead already started in tmux, timed from
send to the last result, with start and exit excluded. Tokens are input + cache creation + cache read + output,
lead and workers together. The harness checked every run afterwards with the full fixture suite.

## Findings, with cause and fix

### Crew engine (`scripts/atlas_crew.py`)

1. The green-check guard ran each worker's unit check one after another: 4.06 s on the fixture. It now runs them
   at once: 1.19 s. Test `test_green_check_guard_runs_the_unit_checks_at_once`.
2. The check cache was unsound. A test file was marked verified when its owner's files were unchanged, but a
   change to a file it imports (a peer's module, a `conftest.py` above it, a package `__init__.py`) was not
   seen, so a broken peer passed as green. The cache now walks the local imports of each test (up to 500 files)
   and needs every reached file's digest to match. Tests: `CheckCacheTests`, including
   `test_peer_file_reached_by_import_outside_needs_runs_the_file`.
3. `summary.ok` meant "global check green" only. A crew with a crashed worker or a killed run still read ok. ok
   now also needs no failed worker and no kill. The summary lists `failed_workers`, `late_exits`,
   `pending_exits` and `killed`.
4. A worker that died (OOM, kill -9), never started, or whose tmux window failed to open was not noticed. The
   supervisor waited for the whole `--wait` budget. Each launch now writes a pid file. A dead pid is recorded
   as exit 137 `died` within 0.5 s, no pid after 60 s as `died`, and a failed `tmux new-window` as exit 126
   `launch_error`.
5. `atlas_crew.py kill` left the supervisor, the claude process groups, the wrappers and the IRC gateway running,
   and wrote no summary. On a finished run it overwrote the real summary. Kill now writes a killed marker,
   stops all of them, writes a killed summary, and leaves a finished run's summary alone (`already_finished`).
6. On a green check the summary waited for every worker to exit, so a worker that had posted DONE but kept its
   claude process open held the lead up. The supervisor now stops DONE workers (SIGTERM, then SIGKILL after
   3 s), publishes the summary at once, then records late exits for up to 30 s.
7. A worker that changed files after posting DONE could leave a broken file under an ok summary. A live repro
   empties `a.py` after DONE: on 17.16.0 the run reported ok. Now a worker whose DONE digest no longer matches
   has its unit check re-run and is failed if it is red. The same repro gives
   `ok: false, failed_workers: [a: "files changed after its DONE and its check now fails (exit 1)"]`, exit 1,
   and no leftover process.
8. The `next` command in the launch output could not be run as printed. It is now
   `atlas_crew.py wait --run <id> --root <root>` with absolute paths.
9. Without tmux the IRC gateway process outlived the run. It is now stopped at run end.
10. Workers ran in the supervisor's process group. They now start in their own session, so a kill reaches
    the whole worker and no stray child is left.
11. `wait` on a run directory the engine never started printed what it found as the result. It now refuses a
    run with no `supervisor.pid`.

### IRC bus, inbox and mux

12. `atlas_irc.drain` read the history twice, so a message posted between the two reads was skipped. It now
    reads once. Test file `scripts/test_atlas_irc_races.py`.
13. A worker's DONE was not posted again when its files changed after the first DONE, so the supervisor
    trusted the old digest. `_announce_done` now re-posts on a new digest.
14. The worker inbox hook treated real messages as filler pings and dropped them: any message with non-ASCII
    text, and words like check, tests, task, work and running. Only true filler is dropped now. Test file
    `hooks/test_worker_inbox_ping.py`.
15. A DONE posted before a fix round counted as fresh, so a worker sent a fix could stop without making it. A
    DONE now counts only if it is newer than the last fix message to that worker or channel. Test file
    `hooks/test_crew_worker_fixround.py`.
16. `atlas_mux.py wait` read an exit file left by an earlier run of a worker with the same name as this run's
    exit, and returned at once. `_exited` now ignores files older than the window's creation.

### Stop gate

17. The circuit breaker counted SubagentStop events, so workers finishing could trip it, and once tripped it
    stayed off for the whole session. Only the main Stop counts now, and it re-arms after a quiet window.
    Bypass rows are kept as their own type and are not counted as hook crashes by the doctor or the dashboard.
18. A test re-run that timed out (exit 124) was reported as a test failure ("fix the failure") with the full
    paperwork list, and every later Stop ran it again. Timeouts, a missing pytest (127) and pytest usage or
    nothing-collected (4, 5) are now inconclusive. They are recorded once and not retried. The cap is 100 s
    inside the 150 s hook.
19. A project venv runner (`.venv/bin/python -m pytest`) was not accepted, so those projects fell back to the
    paperwork tail. Project-local runners are accepted only when their realpath is in the project, or they are
    a symlink onto python3 or pytest under a standard prefix, and only when the session itself ran that exact
    command.
20. The gate re-ran a test command even when the call had been denied by a hook or by the user, or never ran.
    It now re-runs only a command whose transcript result shows it executed: a non-error result, or one Claude
    Code marks `Exit code N`.
21. A hand-written `summary.json` with `ok: true` waived the paperwork, so the green crew proof could be forged.
    A crew now counts green or red only if this session ran the plugin's own `atlas_crew.py run` or `wait`
    (checked by realpath) and that call printed the engine's summary for that run id. Display callers with no
    transcript (`atlas_gates.py`, the omp panel) still show the proof, marked `launch_checked: false`, and
    `atlas_gates.py` finds the session transcript itself when it can.
22. A session ending blocked on a real red was still asked for the full paperwork list. With a blocked header
    and an engine-verified red re-run or crew, the letters a, b, g, k, m and o are dropped. A self-made red
    (pytest exit 4 or 5, a forged summary) does not count.
23. The delegation pre-warning fired in directories where the gates are not armed. It is now silent there.
    The no-test-command reason went from 3,873 B to 776 B on the verifier's fixture.

### Session hooks

24. UserPromptSubmit wrote `.atlas/` into any working directory, including bare dirs and `/tmp`. A
    `/tmp/.atlas` made 9 tests fail, and the status segment showed Atlas in directories that are not Atlas
    projects. Scope is now stored only in an existing Atlas project.
25. SessionStart created `.atlas/.run/*.lock` files in any directory. It no longer does.
26. In a plain git repo, SessionStart left `.atlas/.run/git-clean-stamp.json` untracked (`git status` showed
    `?? .atlas/`). The stamp is now written with the run dir's `.gitignore`.
27. The router's nudge still carried placeholders on some paths and was repeated on every prompt. A
    single-file prompt got two implementers and a crew. The nudge now has no placeholders, shows once per
    session, and sends a single-file task to one worker.
28. The dispatch tripwire demanded a lean-ctx TOOLS block, and nudged `ctx_read` and `ctx_shell`, when lean-ctx
    was not installed, so dispatches were denied for tools that did not exist. The demand and the nudges now
    name only tools that are reachable.
29. The tripwire's finding hint could not be run (no `--title`; the status choice was written as one argument,
    which exits 2). It now prints a runnable `atlas_finding.py` command.
30. `memory_capture` ignored `ATLAS_HOME` and opened no database. It now uses `atlas_db.db_path()`.
31. The recall gate locked the whole session when a configured memory server was not mounted. It now denies
    once and releases when the server comes from the plugin, or when its recall tool is missing. A mounted
    server is still denied on every call until recall happens.
32. `channels.json` was written through a fixed `channels.json.tmp`, so two hooks firing at once crashed with
    FileNotFoundError or lost a write. The new concurrent-writer test fails 5 of 5 times on 17.16.0. Writes now
    use a unique temp file and `os.replace`.

### Doctor (`scripts/atlas_doctor.py`)

33. Under `--plugin-dir`, SessionStart warned that the plugin was missing from `installed_plugins.json` and
    printed a fix command with a placeholder path. Plugin-dir installs are now detected, and the command is
    absolute and quoted.
34. hooks-wired checked only that hook files exist. It now fails on a missing module, a parse error or a
    missing `main()`.
35. The `--fix` advice appeared for checks `--fix` cannot repair (output-style, clone and version failures).
    Those now get their real remedy.
36. db-writable and hook-faults passed when `ATLAS_HOME` could not be created. They now fail.
37. display-statusline accepted another install's status line script. It now flags it, and `--fix` repoints
    it.
38. `CLAUDE_CONFIG_DIR` was ignored, and an unreadable `settings.json` passed. Both are handled now.
39. `--set-status` accepted any status and any id and exited 0. An unknown status or a non-numeric id now
    exits 2, an unknown id exits 1, and the help text lists the statuses the database holds (including
    wontfix and resolved, which the dashboard writes).
40. Runtime files under `.atlas/.run` were not git-ignored. The run dir now gets its own `.gitignore`.
41. A docs-naming lint that crashed reported "names conform", and a project-identity error was swallowed.
    Both now report the error.
42. Model-facing text said "run the atlas-setup skill", which a model cannot do. It now says to ask the user
    to run `/atlas:atlas-setup`.

### CLIs and docs

43. `atlas_todo.py` took an unknown flag such as `--title` as part of the note text. Unknown flags now exit 2,
    and `--` ends options.
44. `atlas_paths` treated a `.git` in a non-project parent (a dotfiles repo in HOME) as the project root.
45. `install_hooks.py` re-installed hooks that the plugin already wires, so they ran twice. Wired hooks are now
    excluded and shown as `[w]` in `--list`.
46. Command examples in skills, references and agents had unquoted `|` (the shell read them as pipes) and a
    missing `--title`. `hooks/test_atlas_contract.py` now checks them.

### Operating contract header

47. The contract's header pattern accepted only glyph-first (`ATLAS | 🏁 done | ...`). A reply that put the
    phase first (`ATLAS | done 🏁 | ...`) was blocked by the Stop gate's (n) check, which cost the lead a full
    extra turn: in the 17.16.0 fixture-8b cold run it was 52,576 more tokens and 2.7 s (34.0 s / 210,915
    against 31.3 s / 158,339). The continuation then passed unchecked because of the `stop_hook_active`
    fail-open. The pattern in `contracts/operating-contract.json` and `mod/contract-pattern.ts` now accepts
    both orders with the phase in group 1; a header with no glyph is still blocked. `_done_claim_reason` in
    `completion_gate_core.py` read the phase as word 3 and now reads group 1; `partialLead` in
    `mod/transcript/leadheader.ts` looks for the phase in the first two words. The `done · ...` line in
    stream-json output is the mod's on-screen rewrite (`displayDelta`); the stored message and the transcript
    keep the contract line, so it is not a bug. Tests: `test_n_accepts_phase_first_header_on_a_fresh_stop`
    and `test_header_pattern_accepts_both_glyph_orders_with_phase_in_group_one`, plus a phase-first case
    in `mod/transcript/rawheader-c23.test.tsx`. `bun test omp mod` (as CI runs it): 4090 pass, 0 fail.
48. SessionStart spawned the detached dirty-snapshot writer (`session_boot.py --snapshot`) in every directory,
    including ones where the Stop gate never acts, so it ran `git status` and hashing for nothing and left
    `.atlas/.run/` behind. Found by the final `-n 16` suite run: the plain-git-repo test failed about 1 run in
    5 when the detached process won the race. The spawn now uses the Stop gate's own arming rule (a docs/
    root, else `atlas_scope.gates_armed`), failing toward spawning on an error. Test:
    `test_dirty_snapshot_spawns_only_where_the_stop_gate_acts` (unarmed: no launch; `ATLAS_GATES=always`:
    one; scratch dir with docs/: one), red before and green after; 10 straight `-n 16` runs of
    `test_session_boot.py` pass.

## Adversarial review

- IRC, mux, crew and CLI fixes: confirmed. The inbox filter (14) was refuted once (it still dropped non-ASCII
  messages) and fixed. The crew needed three rounds (cache import peers, then the stale DONE) and was
  confirmed live.
- Stop gate: four rounds.
  - Round 1 refuted three fixes: bypass rows read as crashes, a symlinked venv interpreter ran an outside
    script, and the red signal could be forged.
  - Round 2 refuted two: hook denials counted as executed, and `echo atlas_crew <id>` forged a crew.
  - Round 3 refuted one: `wait` on a forged dir echoed the run id.
  - Each refutation was fixed and then confirmed on the next round.
  - All five real benchmark crew runs, a real Claude Code transcript and an omp-shaped transcript still get
    their proof and their test re-run.
- Session hooks and doctor: two rounds.
  - Refuted: the recall gate was weakened for mounted servers, the boot stamp was still untracked (its first
    test passed on 17.16.0, so it proved nothing), `--fix` was still advised for output-style, and D12 had no
    test.
  - All were fixed and confirmed.
  - 45 hook and doctor tests and 22 tripwire tests fail on the 17.16.0 code and pass now.
  - Hook timing did not regress: session_boot median 75 ms against 94 ms, prompt_optimizer within noise.
- Full suite: 8803 passed, 5 skipped, both under `-n 16` and serially. The 17.16.0 baseline in this container
  was 10 failed, 8638 passed. Root CI command: 249 passed.

## What is left

- A crew run directory forged in full (run.json, supervisor.pid, supervisor.log, and a summary with a workers
  list) plus a real `wait` call over it still counts. Nothing on disk is unforgeable. A supervisor-written
  nonce outside the repo would close it.
- A copied (not symlinked) venv interpreter is re-run only if the session itself ran it. Otherwise the gate
  takes the paperwork path.
- With workers in their own session, Ctrl-C typed in a tmux pane no longer reaches claude. Use
  `atlas_crew.py kill`.
- The omp mandate twin still denies a configured memory server on every attempt (omp checks the tool set
  itself), which matches the hook for mounted servers.
