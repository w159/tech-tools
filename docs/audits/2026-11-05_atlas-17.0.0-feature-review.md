# Atlas 17.0.0: feature review and measurements

Date: 2026-11-05. Base: HEAD 9e396707 (Atlas 16.12.0). Scope: the whole 17.0.0 change set (default-on anonymous telemetry, Codex parity, skill and agent consolidation, hook latency, test infrastructure, per-seat team labels).

Answer: every area moved in the intended direction and every local gate is green (table at the end). Two things are not proven: the Codex path was never run inside a live Codex model turn, and the telemetry receiver was never run against a real Vercel Blob store. Routing quality is a lexical proxy, not a model measurement.

## What was measured, and how

| Tool | What it does | Where |
|---|---|---|
| `bench.py` | Runs every real command in `hooks/hooks.json` through a shell with an isolated HOME, ATLAS_HOME and project (30 warm runs and 1 cold run per cell), counts skill and agent frontmatter, tokens (chars/4) and repeated lines, and runs `--help` on every CLI script. `--live` measures the working tree; without it, a `git archive` snapshot of HEAD. | scratchpad `measure/bench.py` (not committed) |
| Routing eval | A lexical proxy: BM25 over name, description and `when_to_use` of each skill against labelled prompts (`score.py`, frozen threshold 7.0). It is not model routing. The 179-prompt set was used while tuning descriptions (in-sample); the 90-prompt and 48-prompt sets were held out. | scratchpad `skills-eval/` (not committed) |
| Scorecard | `plugins/atlas/scripts/atlas_scorecard.py run`, deterministic probes of gates, dispatch specs and doctor checks. | in repo |
| Suites | Root pytest, both bun forms, the telemetry receiver's `node --test`. | in repo |

Limits: hook timings vary about 10 percent run to run on this 4-CPU container (SessionStart was 137 to 157 ms across four baseline runs), so compare only runs of the same `bench.py` on the same machine. Token numbers are chars/4 estimates. Raw baseline data: `measure/baseline.json`; the after numbers below are from a `--live` rerun made for this page (`bench.py --live --skip gates,mux_teams,bun,scorecard,harnesses,full_pytest`).

## Codex parity

Status: skills and hooks load in Codex CLI 0.166.0 under a throwaway `CODEX_HOME`. `codex plugin marketplace add` and `codex plugin add atlas@tech-tools` succeed; the app-server `hooks/list` reports 14 hooks; programmer installs and lists `programmer:principles` and `programmer:review` (checked by the workers before this page; counts then were 41 skills and 14 agents, 40 and 11 now).

What exists: `.codex-plugin/plugin.json` for atlas and programmer, `.agents/plugins/marketplace.json`, `hooks/hooks.codex.json` generated by `scripts/gen_codex_hooks.py` (`--check` is a gate and a contract test), `scripts/atlas_harness.py` (harness detection, ask to deny mapping because Codex rejects `permissionDecision: "ask"`, tool-name normalisation for `apply_patch`, `spawn_agent` and `update_plan`), `scripts/atlas_codex_agents.py` (agents as Codex TOML files), and a detached SessionEnd so Codex's 3 s hook limit is met. `hooks/test_codex_parity.py` has 40 tests.

Remaining gaps:

- No live Codex model turn was run (no login). Hook behaviour inside a real turn is covered by payload-level tests only.
- Codex has no Read, Grep or Glob tool, so the read-before-edit nudge only counts MCP reads.
- Hooks must be trusted in Codex (`/hooks`); agents are installed per project or user with `atlas_codex_agents.py` because a plugin cannot ship them.
- The programmer scan-on-edit hook reads `tool_input.file_path`, which `apply_patch` does not carry, so it is a no-op under Codex.
- armada stays Claude-only.

## Telemetry design

On by default, counters only. Whole-number counters per ISO week; after the week ends one payload is posted: the counters, Atlas version, OS family, Python minor version, the ISO week and a random nonce (a fresh UUID per week, used only to drop a retried duplicate). Families: session, hook, dispatch, skill, agent, team, gate, git, security. Every key must be in `telemetry/allowed-keys.json`, which is generated from the client and checked by test and by `diff`; unknown keys are dropped at record time, at payload build and by the receiver. Names inside a key come from files shipped with Atlas, so a user's own skill, repo, branch or path name cannot match.

Never collected: install, session, user or machine ids (there is no install id); timestamps finer than the ISO week; usernames, hostnames, IP addresses, home or working directories, file names or paths; repository, organisation, branch, project or user-defined skill names; prompts, model output, code, commit messages, error messages or file contents.

Controls: `DO_NOT_TRACK=1`, `ATLAS_ANALYTICS=off`, the settings knob, or `atlas_analytics.py disable`. CI and test runs are off unless forced on. A first-run notice is shown once per schema version in all three harnesses. `preview` shows the exact payload and `prove` fails on any identifier-like content (checked in a fresh HOME for this release: RESULT PASS).

Receiver: `telemetry/server` stores only the validated body (`submissions/<week>/<nonce>.json`), never reads IP, headers or user agent, publishes a counter only when at least 3 installs reported it, and folds small version, OS and Python buckets into `other`. Reports are built weekly by `.github/workflows/telemetry-report.yml`, which does nothing until the repository variable `ATLAS_TELEMETRY_URL` is set. Honest caveat: the hosting platform may keep its own request logs under its own retention; the code never reads them.

Hot-path cost: per-event hooks write through `atlas_analytics_hot.py` (stdlib only); the workers' A/B put p50 within 1.5 ms with telemetry on.

## What is not verified

- A live Codex model turn (hooks, skills and agents inside a real session).
- The Vercel Blob backend against a real store. The receiver's tests run against the filesystem store and only check that the Blob backend is selected when `BLOB_READ_WRITE_TOKEN` is set; no Blob call was made, no deployment was made and no data was sent anywhere.
- Model-based skill routing. The routing numbers are a lexical proxy.
- The tmux team benchmarks (need a model API) were not rerun.
- Scorecard probes that bind ports or probe hosts were not run, and the IRC loss probe (D9) is unconfirmed on live panes.
- The 5029 root pytest figure for HEAD, and the duplicated-line and persona token figures, come from worker reports and were not rerun here.
