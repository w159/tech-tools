# Atlas 16.6.0: crew benchmark

Date: 2026-10-29. Question: does the crew reach a quarter of the wall time of
one Claude prompt, on the same tasks and model, after 16.5.0?

Answer: at 30 modules yes (52.3 s against a 57.0 s target, 23.0%). At 18 modules
(26.2%, 2.2 s over) and 8 modules (27.8%, 4.0 s over) not yet. Tokens are
11.8-16.8% of the single prompt (target 50%: met). Numbers below are measured.

## Method

Same harness, fixtures and single-arm baselines as the
[16.5.0 page](2026-10-29_atlas-16.5.0-crew-benchmark.md) and the
[16.4.0 page](2026-10-28_atlas-16.4.0-crew-benchmark.md).

- Model `claude-sonnet-5-5`, effort `medium`, for the lead and every worker, in
  both arms.
- Fixtures: 8 modules (213 tests), 18 modules (469 tests), 30 modules (784 tests).
- Wall time: process start to process exit, measured outside the process. Each
  cell is the median of 3 runs.
- Every run passed every test (pytest rc 0, 0 failed).
- Container: 4 CPUs shared by every worker.

Single-arm medians (copied from the 16.4.0 page, not rerun):

| Task | Wall (s) | Tokens | Cost (USD) |
| --- | ---: | ---: | ---: |
| 8 modules | 144.1 | 852,781 | 0.568 |
| 18 modules | 181.2 | 2,294,556 | 1.205 |
| 30 modules | 227.8 | 3,211,576 | 1.627 |

## What changed since 16.5.0

- Workers omit stub docstrings; `irc check` restores them. The `ranges.py`
  output went from about 4,041 to about 3,600 tokens and its API call from about
  22.7 s to about 20.0 s. `ATLAS_CREW_SKIP_DOCSTRINGS=off` disables it.
- `ATLAS_CREW_WORKER_EFFORT` and `ATLAS_CREW_WORKER_MODEL` override the worker
  effort and model. Defaults unchanged.
- Early own-code check while needs are pending. `ATLAS_CREW_EARLY_CHECK=off`
  disables it.

## Floor evidence

### 8 modules

Best wall time of every skill run ever recorded at 8 modules is 36.8 s; none is
at or under the 36.0 s target. Components in the v18 runs:

| Component | Time |
| --- | --- |
| Lead boot | 5.7 s |
| Crew | 25.5-28.5 s |
| Root module `ranges.py` (one model call, API time) | 19.8-21.1 s |
| Worker non-API time | about 2 s |
| Dependents plus final check | 0.8-4.7 s |
| Lead reply and post-turn | 5.7-8.3 s |

- The `ranges.py` call writes 3,526-3,713 output tokens, of which about 800-930
  are thinking. Thinking cannot be turned off on Sonnet 5.5 (Claude Code model
  configuration docs, `code.claude.com/docs/en/model-config.md`); effort is the
  only lever, and low effort still produced 804 thinking tokens.
- The lead's post-turn work includes the harness `post_turn_summary`, about
  3.6 s in `fixture-skill-ltime-1/lead.log`. Both arms pay it.
- The earlier split experiment was slower because `Range.__init__` cannot be
  divided.

### 18 modules

Best run 43.9 s; mean of 12 runs 48.9 s. Components: boot about 7 s; root
`inline.py` DONE at about 29-31 s; tail 2.8-6.3 s from leaf workers' first-check
fix rounds that only appear once peers are real (the early check caught 1 of
these in 9 runs); lead post about 6.4 s. Inferred floor 44.5-46.4 s, against a
45.3 s target.
