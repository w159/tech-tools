# Atlas 17.20.0: expert audit across atlas, armada and programmer

Date: 2026-11-14. Base: main cd5a30c (atlas 17.18.0), rebased onto 17.19.0 (telemetry, a separate change). The benchmark and fail-before runs below were on the tree before that rebase. Ask: "Keep finding things to improve or what isn't working
as best as it could. Everything should work like an expert." Telemetry was handled in a separate change and is not
covered here.

## Method

Four critics, each on a different model from the lead, read the code and tried to break it:

| Area | Critic model |
|------|--------------|
| Skills, routing, install | claude-sonnet-5-5 |
| Mods (HUD, band, panel) and status line | claude-fable-5-2 |
| Hooks, Stop gate, doctor | claude-opus-5-5 |
| armada and programmer | claude-opus-5-5 |

A finding counted only when it was reproduced. Each fix has a test that fails on the 17.18.0 code and passes
after. Findings are ranked by how much a user would feel them.

## Benchmark

All runs: claude-sonnet-5-5, effort medium, same model for lead, workers and plain. Harness
`/home/user/bench/arm.sh`, 4 CPUs, runs one at a time. Warm = a started lead (start and exit excluded); cold =
`claude -p` (start and exit included). Tokens = input + cache creation + cache read + output, lead plus workers.

| Fixture | Arm | Mode | Wall s (n=3) | Mean s | Tokens (mean) | vs plain, same mode |
|---------|-----|------|--------------|--------|---------------|---------------------|
| 8 modules, 434 tests | plain | cold | 53.6, 50.9, 54.4 | 53.0 | 326k | - |
| 8 modules | plain | warm | 46.3, 46.6, 52.8 | 48.6 | 278k | - |
| 8 modules | atlas 17.20.0 | cold | 29.4, 27.3, 25.9 | 27.5 | 147k | 52% time, 45% tokens |
| 8 modules | atlas 17.20.0 | warm | 23.5, 22.6, 22.8 | 23.0 | 149k | 47% time, 54% tokens |
| 8 modules | atlas 17.18.0 | cold | 29.4, 25.5, 27.1 | 27.3 | 167k | 52% time |
| 8 modules | atlas 17.18.0 | warm | 23.2, 26.3, 22.4 | 24.0 | 150k | 49% time |
| 16 modules, 869 tests | plain | cold | 120.7, 119.8, 115.1 | 118.5 | 605k | - |
| 16 modules | plain | warm | 113.0, 121.4, 120.7 | 118.4 | 659k | - |
| 16 modules | atlas 17.20.0 | cold | 30.9, 29.1, 33.5 | 31.2 | 215k | 26% time, 36% tokens |
| 16 modules | atlas 17.20.0 | warm | 28.8, 27.9, 29.6 | 28.8 | 215k | 24% time, 33% tokens |
| 16 modules | atlas 17.18.0 | cold | 31.3, 31.6, 32.2 | 31.7 | 219k | 27% time |
| 16 modules | atlas 17.18.0 | warm | 27.4, 27.6, 29.3 | 28.1 | 216k | 24% time |

Every run passed every test (434 and 869). Lead turns: atlas 2 (one 17.18.0 cold run took 3, 195k tokens);
plain 5-8 at 8 modules, 11-12 at 16.

Reading: 1/4 of one prompt's wall time is met warm at 16 modules (24%) and almost cold (26%). It is not met at
8 modules (47-52%). 50% of the tokens is met everywhere except 8 modules warm (54%), where the plain warm runs
happened to use few turns. This release did not change crew time: 17.18.0 on the same box is within noise of
17.20.0 at both sizes. The 16-module ratio is better than the 29% reported for 17.18.0 because the plain prompt
took 118 s here against 92 s on the earlier 842-test fixture and box, not because the crew got faster. The
short lead view saves about 1-2% of tokens (215k against 216-219k at 16 modules).

## Not changed

- Spinner glyphs differ between the band and the panel. Unifying them breaks the external capture scorer, which
  reads the circle glyphs (`SCORER_READS_CIRCLES` in `contracts/hud-golden.ts`, about 110 tests).
- The shipped armada bundles (CIPP, Auvik, gateway) were built before the Oct 27 dependency bumps. Suggested:
  pin esbuild 0.28.2, tsup 8.5.1, node 22 and diff a CI rebuild against the shipped files. The Auvik bundle was
  rebuilt here with the same 39 tools.
- An async guard for the crew launch (about 1 s) was not built: it adds a race between the guard and the launch.
