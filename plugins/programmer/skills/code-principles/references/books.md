# Book-derived review corpus

This is the operational map for the `code-review` skill. Every finding must cite
one lens and one source book. The map is deliberately compact: it exists to keep
reviews explainable, not to replace the books.

| Book | Review lens | Core principles |
|---|---|---|
| Agile Software Development | Delivery & feedback | Iterative delivery, sustainable pace, continuous feedback, refactoring, short cycles. |
| Clean Architecture | Architecture | Dependency rule, boundaries, SRP, OCP, LSP, ISP, DIP, stable abstractions, use-case-centered design. |
| Clean Code Collection | Craft | Intent-revealing names, small functions, focused comments, explicit errors, safe boundaries, tests, concurrency. |
| Dependency Injection: Principles, Practices, Patterns | Composition | Program to interfaces, explicit dependencies, composition root, lifetime ownership, testability. |
| Design Patterns (GoF) | Design patterns | Encapsulate what varies, program to interface, composition over inheritance, pattern fit over pattern worship. |
| Designing Data-Intensive Applications | Data & distribution | Explicit consistency, replication, partitioning, schema evolution, idempotency, observability, failure handling. |
| Domain-Driven Design | Domain | Ubiquitous language, bounded contexts, aggregates, domain events, anti-corruption layers. |
| Extreme Programming Explained, 2nd Ed. | Process | Small releases, continuous integration, collective ownership, sustainable pace, simple design, test-first. |
| Five Lines of Code | Readability | Small functions, low nesting, minimal branching, obvious intent, small refactor steps. |
| Growing Object-Oriented Software, Guided by Tests | Testing | Walking skeleton, end-to-end tests, test doubles, test-driven design, incremental architecture. |
| Hands-On Design Patterns with Swift | Patterns | Pattern fit, protocol-oriented design, immutability, ownership, testability. |
| Head First Design Patterns, 2nd Ed. | Patterns | Pattern intent, encapsulate variation, composition, open/closed design, dependency inversion. |
| Object-Oriented Software Engineering (Jacobson) | Requirements | Use cases, actors, scenarios, traceability, requirements as the source of tests. |
| Object-Oriented Software Construction (Meyer) | Contracts | Preconditions, postconditions, invariants, command-query separation, explicit exceptions. |
| Object-Oriented Analysis and Design with Applications (Booch) | Object design | Responsibility assignment, abstraction, modularity, cohesive collaborations. |
| Patterns of Enterprise Application Architecture | Application architecture | Repository, unit of work, service layer, transaction boundaries, explicit domain models. |
| Refactoring | Maintainability | Code smells, small safe steps, behavior preservation, test-backed change, naming intent. |
| Building Microservices | Service boundaries | Service autonomy, data ownership, API contracts, observability, resilience, explicit deployment seams. |
| Software Design Decoded | Judgment | Simplicity, cognitive load, expert heuristics, collaboration, context-aware design. |
| Software Engineering: A Practitioner's Approach | Process | Requirements, reviews, testing, maintenance, risk, quality attributes, iterative correction. |
| Test-Driven Development by Example | Testing | Red-green-refactor, test-first, small steps, behavior-oriented tests, simple design. |
| The Pragmatic Programmer, 20th Anniversary Edition | Cross-cutting | ETC, DRY, orthogonality, contracts, crash early, testing, naming, security, ethics. |
| The Software Architect Elevator | Architecture | Business-technology alignment, evolution, trade-offs, communication across organizational layers. |
| User Stories Applied | Requirements | Small stories, acceptance criteria, conversation, iteration, user value. |
| We Programmers | Craft & ethics | Craftsmanship, responsibility, collaboration, learning, human judgment. |
| Writing Effective Use Cases | Requirements | Actor-goal-system form, scenarios, exceptions, testable behavior, system boundaries. |
| Structure and Interpretation of Computer Programs | Abstraction | Abstraction, immutability, higher-order functions, explicit state, modularity. |
| Software Architecture in Practice, 4th Ed. | Quality attributes | Security, performance, availability, testability, modifiability, architecture tactics. |
| The Essentials of Modern Software Engineering | Practice | Principles over ceremony, feedback loops, empirical control, intentional practices. |
| Use-Case 2.0 | Requirements | Slim use cases, test-driven slices, iterative discovery, scenario-driven delivery. |
