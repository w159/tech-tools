# Display checks (full table)

The settings file is `$CLAUDE_CONFIG_DIR/settings.json` (default `~/.claude/settings.json`).

| Check | Looks for | `--fix` |
|---|---|---|
| `display-todo-tools` | `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` and `CLAUDE_CODE_ENABLE_TASKS=0` in settings `env` or the process env (Claude Code 2.1.233+). The first gives every model the TodoWrite tool; the second keeps Claude Code on TodoWrite instead of the Task tools, whose own checklist Claude Code draws and re-expands above the prompt on every TaskCreate/TaskUpdate, squeezing the Atlas TODO tree and band to about 6 rows. WARN if either is missing. | Merges `"env": {"CLAUDE_CODE_ENABLE_TODO_TOOLS": "1", "CLAUDE_CODE_ENABLE_TASKS": "0"}`, keeps every other key, atomic write. Invalid JSON is never written. |
| `display-mod` | `hooks/hooks.json` lists `../mod/register.ts` in `modules` and the file exists; `ATLAS_MOD` / `ATLAS_HUD` are not `off`. | Report only. The switches are a user choice: remove them from settings `env` and the shell profile to undo. |
| `display-todo-mirror` | The `PostToolUse` matcher in `hooks.json` covers every tool `todo_capture` is dispatched for (`event_dispatch.py`). | Report only (update the plugin). |
| `display-statusline` | `statusLine` runs `atlas_statusline.py`. | Sets it to `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/atlas_statusline.py"` (the installed plugin root written out as an absolute path) with `refreshInterval: 5` when unset or pointing at a missing Atlas script, and adds `refreshInterval: 5` to a live Atlas entry that lacks it (the one-row compact mode needs the line re-run every few seconds). A statusLine from another tool is reported and never overwritten. |
| `display-harness` | `claude-code`, or under `ATLAS_HARNESS=omp` whether the omp extension that draws mission control is registered (same result as `omp-bridge`). | Report only. |
| `display-omp-todo` | omp's TODO tree renders only from omp's native `todo` tool, which `todo.enabled: false` removes. Reads `todo.enabled` from `$PI_CODING_AGENT_DIR` (default `~/.omp/agent`) `config.yml`/`config.yaml` and the project's `.omp/config.yml`, `.omp/settings.json`, `.claude/settings.json`; the project layer wins. WARN when the effective value is false. n/a when no omp settings file exists. `tools.xdev` needs no check: omp pins `todo` top-level in every xdev mode. | Sets `todo.enabled` to `true` in place (YAML edited line-wise, comments and other keys kept; JSON rewritten atomically). |
| `display-hud` | `ATLAS_HUD` is not exactly `off` (the only value `mod/register.ts` honours; `OFF`, `0`, `false` leave the HUD on) in Claude Code settings `env` (user `settings.json`, project `.claude/settings.json` and `settings.local.json`); `off` hides the TODO tree and Subagents block together. Appends an INFO note, never a failure, when the terminal is under 30 rows, because Claude Code caps the area above the prompt at half the terminal and the HUD collapses. | Removes the `ATLAS_HUD` key from every settings file that sets it off, keeps everything else. |
| `display-renderer` | Effective Claude Code renderer is not fullscreen. `tui` is read from user `settings.json`, project `.claude/settings.json` and `settings.local.json` (later wins); `CLAUDE_CODE_NO_FLICKER=1` also means fullscreen, while `CLAUDE_CODE_NO_FLICKER=0` or `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN` turns it off. Fullscreen makes the TODO tree, Subagents, prompt, status line and mode line share one area capped at half the terminal rows, so Atlas gets only what is left (none at 24 rows); the default renderer draws them above the prompt like omp. WARN names the layer or env var. | Sets `"tui": "default"` in the layer whose value made it fullscreen, keeps every other key. If only the env var forces it, files are untouched and the WARN says which variable to unset. Undo with `/tui fullscreen`. |
