# Atlas enforcement for omp

- In projects with a `docs/` directory in cwd or an ancestor, native `grep` and `glob` are blocked in main and subagent sessions only when a replacement is callable in THIS session, decided per call from `pi.getActiveTools()`: a bare `ctx_search`/`ctx_glob` tool is named directly; otherwise a live lean-ctx MCP device (`xd://mcp__lean_ctx_ctx_search` / `_ctx_glob`, which needs the `write` tool). The lean-ctx binary on PATH or a configured-but-inactive server never arms the deny; with nothing reachable the call is allowed with a one-time nudge, and unknown availability allows silently.
- Native `read` and `bash` stay allowed, with one nudge per tool per session naming the reachable route (silent when none is reachable): `ctx_read` for exploration (native Read before Edit remains fine), `ctx_shell` / context-mode `ctx_execute` for output over roughly 20 lines (native Bash remains fine for mutations and short output).
- Main-thread `edit`/`write` calls outside `docs/`, `.atlas/`, and `*.md`, excluding internal URIs, require a main-thread `task` dispatch. `session_stop` returns a real `{ decision: "block", reason }` refusal once per session, asking the orchestrator to dispatch the code change to a subagent and verify. The next stop is allowed; this is not a persistent refusal and cannot loop. In-process subagents and tmux colony workers (see the "Tmux colony workers" bullet below) are exempt. In-turn tracking is of `edit`/`write` tool calls; at `session_stop` the gate also diffs the dirty non-docs snapshot to catch shell-written code (`delegation.ts`).
- Atlas-bound task dispatches that omit per-item `name` get a one-time `additionalContext` hint telling the lead to name items; a task item's `name` doubles as its spawn handle and its sibling address (`write agent://<name>`). Non-blocking; omp auto-names omitted items.
- The extension factory sets `CLAUDE_PLUGIN_ROOT` to the atlas plugin root (resolved from the module's own location, only when `scripts/atlas_todo.py` exists there) when the variable is unset or empty. omp substitutes that placeholder only during Claude-plugin discovery, so it is unset for omp-native agents; with the factory default, workers can run `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/atlas_todo.py" ...` from bash. A pre-existing value is preserved only while `<value>/scripts/atlas_todo.py` exists there; a stale or foreign value is replaced.
- Board mirror: every successful main-thread `todo` tool result in a docs-scoped project mirrors the lead's full plan into `<project>/.atlas/.run/todos.json` by spawning `python3 <plugin-root>/scripts/atlas_todo.py set --root <project> --session <omp-session-id> '<JSON array of {content,status}>'`. omp's `todo` tool is never mirrored by omp itself (unlike Claude Code's TodoWrite), so this is what gives omp workers claimable board items. Statuses outside the board vocabulary (`blocked`, `abandoned`) normalize to `pending`; the spawn is detached and fire-and-forget, and any failure (including a missing session id) fails open without touching the session.
- Output style: `omp/style.ts` appends `output-styles/atlas-orchestrator.md` (frontmatter stripped, Claude tool names translated via `contracts/tool-names.json`) to the MAIN session's system prompt from `before_agent_start`; subagents get nothing, as in Claude Code. A second marked block, `omp/lead-addendum.md` (omp-only lead guidance; it lives in `omp/`, not `output-styles/`, because Claude Code scans that directory), follows it. Both blocks are rendered once per session and re-served byte for byte until `session_start`/`session_switch`: the style text depends on which tools are callable, and re-rendering after `xd://` devices mount changed the system prompt mid-session, which made the provider's prompt cache rewrite every token after the shared prefix. A render that fails (unreadable source) is not frozen. `ATLAS_STYLE=off` disables both.
- Tool mandates (`omp/mandates.ts`, text in `contracts/mandates.json`): a "Recall first" system-prompt line naming the live claude-mem search device (only when one is callable; once rendered it is frozen for the session like the style, an absent line never is), and a one-time `additionalContext` nudge to run ponytail-review on the staged diff before a main-thread `git commit` (only when `ponytail-review` is listed in the session's skills). `ATLAS_MANDATES=off` disables both.
- Hook bridge (`omp/hook-bridge.ts`): runs the Claude Code hooks marked bridgeable in `contracts/hook-bridge.json` (`bridged`) straight from `hooks/hooks.json` — SessionStart on the first main prompt (its context is appended to every main prompt), UserPromptSubmit on each main prompt, PreToolUse on `tool_call` (a deny blocks the call), PostToolUse on `tool_result`. Hooks run via `/bin/sh` with `CLAUDE_PLUGIN_ROOT`, `ATLAS_HARNESS=omp`, `ATLAS_MANDATES=off`, `ATLAS_NATIVE_POLICY=off`, `ATLAS_TOOLKIT_LOAD=omp` (see the tool-hook bridge additions below). An omp `write` to an `xd://mcp__…` URI is an MCP device call, so the bridge reports it to the hooks as that MCP tool (`claudeNamesForCall`, split like `omp_transcript._split_mcp_xd`), not as `Write`. Failures allow. `ATLAS_HOOK_BRIDGE=off` disables it. `todo_capture.py`, `atlas_doctor.py` and `recall_gate.py` stay unbridged (each with its reason in the contract).
- Worker output budget (`omp/workers.ts`): subagent provider payloads have their output-token field (`max_tokens`, `max_completion_tokens`, `max_output_tokens`, ollama `options.num_predict`) lowered to `ATLAS_WORKER_MAX_TOKENS` (default 32000). Never raised; payloads whose Anthropic thinking budget would exceed the cap are left alone.
- Advisor gate (`omp/advisor.ts`): advisor notes of severity `concern`/`blocker` become board items (`advisor[<severity>]: ...`); `session_stop` blocks up to 3 times while any is open. Close each with `atlas_todo.py complete --id <id> --evidence ...`. `ATLAS_ADVISOR_GATE=off`.
- Recall gate (`omp/mandates.ts`): when a claude-mem search device is callable, the first main-thread tool call that is not a claude-mem call (or `todo`) is blocked on every attempt until a real claude-mem call happens.
- Exploration-only `bash` (cat/grep/find/ls/... with no writes) is blocked toward the matching lean-ctx tool when a shell replacement is reachable; every `bash` runs through `lean-ctx -c` when the binary resolves and a lean-ctx route is active (`omp/shell-route.ts`, `ATLAS_LEAN_SHELL=off`).
- Delegation gate also counts code written through the shell: `omp/delegation.ts` snapshots dirty non-docs paths (git status + content hash) at session start and diffs them at stop. Directories agent tooling writes by itself (`ompToolStateDirs` in `contracts/native-tools.json`, e.g. `.serena/`) are not code and are exempt there; the key is read by omp code only, so Claude Code's gate is unchanged. The bridged Python gate compares against the SessionStart snapshot, which omp takes before MCP servers start, so the Stop bridge runs `omp_runstate.py rebaseline` (awaited, 3 s budget, immediately before `completion_gate.py`) to fold tool state that appeared or changed since into that snapshot. Only `ompToolStateDirs` paths are ever absorbed; a real code edit still counts.
- Child processes go through `omp/proc.ts` (temp-file stdio), which works under every `bun test` invocation form on hosts where piped child stdio breaks.
- Native-tool kinds, replacements, and the delegation exemption come from `contracts/native-tools.json` via `omp/contracts.ts`, shared with the Python hooks; an unreadable contract allows everything.
- `ATLAS_GATE=off` disables the Stop-time delegation check. `ATLAS_TRIPWIRE_HARD=off` allows grep/glob; Read/Bash nudges remain. Internal errors fail open. Outside docs-scoped projects all checks are silent.
- Session-end bridge (`omp/stop-bridge.ts`, wiring in `contracts/hook-bridge.json` `bridgedSessionEnd`, order from `hooks/hooks.json`):
  - `session_stop` (main only) runs the Claude `Stop` chain. `scripts/omp_transcript.py convert` turns the omp session file (`event.session_file`) into a Claude-shaped transcript BEFORE any hook runs, because the completion gate and the ingest hooks re-read it from `transcript_path`. All five hooks (`completion_gate`, `ingest_session`, `chronicle_facet`, `memory_capture`, `nudge`) run in hooks.json order even after the gate blocks (the capture hooks must not be starved); the first `{decision: "block", reason}` becomes the omp `session_stop` result `{decision: "block", reason}`, not plain context.
  - Self-limits (omp does not cap what a bridged Stop hook refuses): at most 3 consecutive bridged blocks per session, the streak resets on `session_start` / `session_switch` and when a Stop passes; when omp reports `stop_hook_active`, a block that repeats the previous reason is dropped.
  - Composition: the bridge registers before the advisor and delegation gates, and omp keeps the FIRST `block` across handlers, so only one refusal reaches the model. The later gates still evaluate and spend their own allowance (delegation: once; advisor: 3), so a delegation or advisor refusal can be forfeited while the bridged gate is blocking.
  - `session_shutdown` (fires for main AND subagent sessions, omp caps it at 2 s) converts the transcript with a 1.2 s budget and spawns `ingest_session.py` DETACHED, never awaited: `SessionEnd` for main, `SubagentStop` for sub (the detached ingest converts into its own `atlas-ingest-*` directory, which the child removes on exit; the `.../subagents/agent-<id>.jsonl` path shape that `dispatch_tripwire` reads as "subagent" is only used for the tool-hook transcripts the cache makes). `auto_compaction_start` spawns the same ingest as `PreCompact`, throttled to once per 60 s per session. `session_before_compact` is deliberately not used: registering a handler for it disables omp's async compaction. Spawns are bounded per session (4 per event, 12 total, tracked sessions pruned at 64).
  - `ATLAS_STOP_BRIDGE=off` disables this module, `ATLAS_INGEST=off` suppresses the detached ingest spawns, `ATLAS_HOOK_BRIDGE=off` disables every bridge. A broken or hung converter, hook or spawn degrades to "no transcript" / "no ingest"; nothing blocks or wedges the session.
- Tool-hook bridge additions (`omp/hook-bridge.ts`): `PostToolUse` payloads carry `tool_response` (the result content, JSON-stringified unless already a string), `is_error` and `transcript_path`. omp `task` batches run as one Claude `Task` dispatch per item (`claudeTaskInputs`: `atlas:<agent>` for colony agents, `description` from `name`, `isolated: true` as `isolation: "worktree"`); the `prompt` the hooks read is the batch-level `context` followed by the item's `task`, because omp gives every child both and tells the lead to put the shared `# Goal`/contract in `context`; reading `task` alone denied well-formed dispatches as unbounded or missing TOOLS. Any denied item blocks the batch. `dispatch_tripwire.py` (inline-op tiers, production-edit deny, dispatch-spec deny: GOAL/DELIVERABLE/SUCCESS CRITERIA/OUT OF SCOPE/STOP CONDITIONS, one GOAL per dispatch, code-nav TOOLS block) is bridged for every matched tool, including `Read`/`Grep`/`Glob`/`Bash` PreToolUse, because its inline-op threshold deny lives in PreToolUse and counts exactly those tools (skipping them removed the deny tier). Two env vars, set only by this bridge and read only by `dispatch_tripwire.py`, adapt it to omp: `ATLAS_NATIVE_POLICY=off` makes it skip its own native-tool deny/nudge text (`omp/index.ts` already produces it) while still reaching the threshold tiers; `ATLAS_TOOLKIT_LOAD=omp` waives only the `ToolSearch` load step of the TOOLS requirement (omp has no such tool), keeps the named-navigation-tool requirement, and makes the deny text a paste-ready one-line `TOOLS:` instead of a `ToolSearch` instruction. Claude Code sets neither, so its behaviour and deny text are unchanged. omp mints `mcp__<server>_<tool>` with one underscore, so `connector_credential_watch.py` gets the Claude-style `mcp__<server>__<tool>` re-split from the `connectorWatch` list in `contracts/mcp-servers.json` (`plugin_atlas`, `falcon-mcp`, `cipp`, `connectwise`, `plaid`, `gcloud`, longest prefix first); other MCP names pass through unchanged. Subagent tool hooks get a converted `/subagents/` transcript path; the lead's tool hooks get an empty one (no bridged tool hook reads the lead's transcript, and an empty path reads as "main").
- Run state (`omp/run-state.ts`, `scripts/omp_runstate.py`): the main session's first `session_start` calls `begin` then `snapshot` (the runs row and `.atlas/.run/dirty-snapshot-<sid>.json`). Every main-session turn then calls `begin` again from `before_agent_start` (`onTurnStart`, wired in `omp/index.ts`; subagents and an empty session id are skipped; no `snapshot`, which stays a session-start baseline). All run-state CLI calls are appended to one promise tail, so they run strictly in call order and never overlap (an `arm`/`event` cannot land before the `begin` that creates its run). `begin` is create-if-absent, so it only opens a run when `current_run_id` is None: a session that continues after a Stop finalized its run (omp does not fire `session_start` again) gets a fresh open run, and the DB gates (`dispatch_tripwire.py`, `completion_gate.py`) keep seeing one. An allowed `task` call calls `arm` (with `--worktree` for isolated dispatches); `task` and `edit`/`write` results call `event`. `arm`/`event` are a fallback used only when the bridged `dispatch_tripwire.py` did NOT run for the call (it logs, arms and marks worktrees itself, and a second writer would double-count dispatches and inline ops). A denied call is never armed or logged. The CLI is only invoked when its file exists, runs are fire-and-forget, and nothing here can block a tool call.
- Model-override deny (`omp/index.ts`): on `before_subagent_spawn` (fires in the parent) omp hands the handler the EXPANDED model patterns plus the pre-expansion `modelRole`, and the `task` tool has no per-call `model`, so the event carries nothing about what the caller asked for. The deny therefore blocks only a concrete selector (contains `/`) that no pinned role explains: every token must be a pinned alias, or a selector while `modelRole` names one of the agent's pinned roles. A selector equal to the parent's live model (`ctx.model` as `provider/id`, with at most one `:<thinking-level>` suffix, case-insensitive) is not an override: on a marketplace install the pinned agents are not discovered, so omp resolves the child to the parent's model, and that inherited selector must not be denied; with no `ctx.model` the handler behaves as before. Comparing the expanded patterns with the unexpanded pinned list, as this handler first did, denied every colony dispatch (measured: four failed spawns in one run, after which the lead dropped `agent` and the work ran on the generic agent). `ATLAS_TRIPWIRE_HARD=off` disables it.
- Tmux colony workers (`scripts/atlas_mux.py`, `ATLAS_MUX=tmux`): each worker is a standalone `omp -p`, which omp reports as a MAIN session (`ctx.agent.kind` is never `sub`), so the extension cannot tell it from a lead by kind. `atlas_mux` pins `ATLAS_WORKER_NAME` in the worker env and that is the leaf marker: (1) the in-extension delegation check skips such a session (its lead owns delegation); (2) `hookEnv` in `omp/hook-bridge.ts` hands every bridged hook `ATLAS_ENGINE_ARM=off`, because `prompt_optimizer.py` arms a session as an orchestrator from its prompt text and a worker's task prompt reads as engineering work, after which `dispatch_tripwire.py` denied every edit the worker was spawned to make (the existing kill switch is used; no Python hook changed). Two `atlas_mux` options keep a worker consistent with its lead: `--omp-extension` / `ATLAS_MUX_OMP_EXTENSION` pins the worker to one atlas tree with `--no-extensions --extension=<path>` (unpinned it loads whichever atlas omp has installed, which can be an older release), and `spawn` forwards the lead's `ATLAS_DB` and `ATLAS_GATE` by name into the pane, because a tmux pane inherits the tmux server's environment, not the spawning client's. The advisor gate and the bridged Stop chain still apply to a worker, so it can be told to close its own advisor items.
  - Lead env forwarded into the pane (`FORWARDED_ENV` in `scripts/atlas_mux.py`, by name; never a copy of the environment): `ATLAS_DB`, `ATLAS_GATE` and, since 9.0.0, the `ATLAS_*` switches a worker session reads (`ATLAS_MANDATES`, `ATLAS_HOOK_BRIDGE`, `ATLAS_STOP_BRIDGE`, `ATLAS_INGEST`, `ATLAS_LEAN_SHELL`, `ATLAS_ADVISOR_GATE`, `ATLAS_STYLE`, `ATLAS_TRIPWIRE`, `ATLAS_TRIPWIRE_HARD`, `ATLAS_WORKER_MAX_TOKENS`, `ATLAS_CONNECTOR_WATCH`, `ATLAS_CHRONICLE`, `ATLAS_MEMORY_CAPTURE`) plus `PI_CODING_AGENT_DIR`, `PI_PROFILE`, `OMP_PROFILE` so the worker runs under the lead's omp profile. Without them a lead's `ATLAS_MANDATES=off` came back on in every worker (the recall gate re-armed). `PATH` needs no forwarding (tmux gives a new window the client's `PATH`, probed); the variables atlas itself pins (`ATLAS_WORKER_NAME`, `ATLAS_PROJECT_ROOT`, `ATLAS_HARNESS`, `ATLAS_TOOLKIT_LOAD`, `ATLAS_NATIVE_POLICY`, `ATLAS_ENGINE_ARM`) are never forwarded.
- Under `ATLAS_HARNESS=omp` the bridged `session_boot.py` ignores `~/.claude/settings.json` `outputStyle` (omp renders its own style) and `tool_routing.plugin_enabled` lets `~/.omp/plugins/omp-plugins.lock.json` decide for plugins it names, so omp-only installs are not reported as "Setup gap: ... absent".

Known limits of the omp bridge:

- `session_shutdown` gives handlers 2 s; if the transcript conversion does not finish inside its 1.2 s budget the ingest is skipped for that shutdown (the Stop-time ingest still ran).
- Each conversion rewrites the whole transcript file at a fixed per-session path; a cursor-based ingest that resumes mid-file depends on the converter being deterministic for the already-ingested prefix.
- Batch `task` dispatches are accounted per path. The bridged `dispatch_tripwire.py` is run once per batch item, so each dispatched agent gets its own dispatch row (verified against the real hook: one `PostToolUse` call writes one `dispatches` row), which is what the completion gate's implementer/verifier pairing counts. The run-state fallback (used only when the tripwire did not run) logs ONE row for a batch, with the first agent, because `omp_runstate.py event --dispatch` takes a single agent type; mixed batches are therefore under-counted on that fallback path only.
- Each detached ingest converts into its own `atlas-ingest-*` directory, and the child removes that directory (payload, transcript and colony sidecars) when it exits.
- Claude Code and omp differ on one point by design: omp exempts agent tool-state directories (`ompToolStateDirs`) from the shell-edit count and rebaselines them at Stop; Claude Code's condition (m) still counts a `.serena/` that appears after SessionStart as a shell edit, because its hooks and `delegationExempt` are unchanged.

## Colony agents (omp-native, generated)

`omp/agents/*.md` are GENERATED by `gen-agents.ts` from the Claude-format sources in `agents/` — never edit them by hand; re-run:

```sh
bun plugins/atlas/omp/gen-agents.ts   # idempotent; commit the output
```

Why generated copies exist: omp discards the frontmatter `model` of Claude-dialect plugin agents (a package with `.claude-plugin/plugin.json` is Claude-format, `pluginUsesClaudeModelDialect`), so the `agents/` sources run model-less on omp. omp instead scans `<extension-root>/agents` for extension packages and keeps `model` + `thinkingLevel` there; extension-package agents are merged first-wins by exact name and precede Claude plugin agents, so these generated copies override the model-less ones (and bundled agents) of the same names. The style paragraph about why `TodoWrite` may be missing (Claude Code env vars and ToolSearch) is rewritten for omp by `adaptTodoGatingForOmp` in `omp/style.ts`; the source file is not changed.

The generated frontmatter adds what omp understands and Claude dialect does not:

- `thinkingLevel` — user-approved map: `off` for explorer, docs-auditor, docs-curator, schema-inventory, naming-glossary-audit, runner; `low` for implementer, planner, db-prober, ui-runtime-tester; `medium` for verifier, completeness-critic, rls-privilege-audit.
- `model` — ordered list: `["@atlas-worker", "@smol"]` for off/low agents (runner, the mechanical tier, uses `["@atlas-mechanic", "@smol"]`), `["@atlas-verifier", "@default", "@smol"]` for medium agents. Role aliases resolve through `modelRoles.<role>`; an unconfigured custom role stays a raw pattern that matches no model (empirically the spawned subagent fails with "No model selected" — there is no automatic parent-model fallback), so each list carries built-in fallback aliases that resolve with no user configuration: `@smol` (omp's cheap role) for workers; `@default` (omp's `modelRoles.default` — the session's main model) for verifiers, then `@smol` as a last resort if `modelRoles.default` is unset, because a cheap verifier beats one that fails to spawn.
- `spawns: "none"` — lead-only dispatch: atlas workers may not spawn subagents.

Point `modelRoles.atlas-worker` / `modelRoles.atlas-verifier` at real models (EXAMPLE — not applied by anything here):

```yaml
# ~/.omp/agent/config.yml
modelRoles:
  atlas-worker: openai/gpt-5-mini:low
  atlas-verifier: openai/gpt-5.2:medium
  default: anthropic/claude-sonnet-5-5:medium   # @default fallback for verifier-tier agents (else @smol)
```

Colony messaging: dispatch atlas agents with named task items (unique, CamelCase, <= 32 chars); a worker addresses its sibling via `write agent://<name>`. Every delivered IRC message (a `write agent://<name>` whose result is not an error, from the lead or any subagent) is mirrored to `<root>/.atlas/.run/board/<sender>.jsonl`, where the sender is `lead` for the main thread or the item name for a subagent, addressed to the target (`Main`/`parent` are recorded as `lead`, `all` stays `all`) with the text cut to 500 chars plus ` [+N chars]`; read them with `atlas_todo.py notes --to <name>`. Shared worker notes go through the atlas board notes CLI — `${CLAUDE_PLUGIN_ROOT}` is set by the extension factory (see above), so these are runnable as-is from any omp worker's bash: `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/atlas_todo.py" note --owner <name> [--to <name|all>] [--item <id>] "<text>"` and `... notes [--to <name>] [--since <ts>]`. An omp process started before a plugin upgrade keeps the old extension and its `CLAUDE_PLUGIN_ROOT`; restart omp after `omp plugin upgrade atlas`.

## Install (not performed automatically)

OMP marketplace installations load this module from the atlas root `package.json` → `omp.extensions: ["./omp/index.ts"]`. A Claude Code installation alone does not discover this nested directory. See [Marketplace concepts](omp://marketplace.md) and [Extension Loading](omp://extension-loading.md) §§ Installed plugin extension entries / Explicitly configured paths.

For an existing source checkout, load the extension package by DIRECTORY so the sibling `agents/` surface is discovered too (file entrypoints contribute zero sub-discovery surface):

```sh
omp --extension /absolute/path/to/tech-tools/plugins/atlas/omp
```

Or add this entry to the existing `extensions` list in the active profile's agent `config.yml` (default `~/.omp/agent/config.yml`), then restart omp:

```yaml
extensions:
  - /absolute/path/to/tech-tools/plugins/atlas/omp
```

Do not replace existing extension entries. Named profiles use their own agent config. No package dependencies or installation into `~/.omp` are required by the source itself.

Note: when atlas is installed through the omp marketplace (Claude-format root), the generated `omp/agents/` directory is not part of the marketplace agent surface. omp 18.6.1 (`src/task/discovery.ts`, `discoverAgents`) reads only `<plugin root>/agents` for a plugin root, and a root with `.claude-plugin/plugin.json` and no `.omp-plugin/plugin.json` is Claude-dialect, so atlas's Claude `agents/*.md` are dispatchable there but run model-less; the `@atlas-worker`/`@atlas-verifier` tiers need the directory load above. omp ignores a manifest `agents` path and gives `omp.extensions: ["./omp/index.ts"]` (a file entry) no sub-discovery, so atlas packaging cannot surface `omp/agents/` without moving files that Claude Code also reads.

## Verification

```sh
bun test plugins/atlas/omp
```

The tests drive the documented handlers with fake events and temporary docs-scoped projects. Runtime contracts: [Extensions](omp://extensions.md), sections Handler context (`ctx.agent.kind`), Prompt and turn lifecycle (`session_stop`, a true blocking primitive rather than notification-only `agent_end`), and Tool lifecycle (`tool_call`, `additionalContext`).
