## Checked and clean (no finding)

- **Token guard.** `POST /api/v2/colony/<name>/send` and `/kill` are mutations, so `_guard` requires `X-Atlas-Token`, `Content-Type: application/json`, and Host/Origin. `GET /api/v2/colony` is in `_SENSITIVE_GET` (`atlas_dashboard.py` regex now includes `colony`). `/api/v2/channels` was already covered.
- **Path traversal in `<name>`.** The URL segment is `unquote`d, but it is only used to match an existing roster entry. It is never joined into a path. The only path built from a name is the `.log` stat/`is_file` in `build_colony`; it is read-only and never opened.
- **Shell injection.** Kill is `herdr pane.close` over the socket, or `os.kill(int(pid), SIGTERM)` with an int. Send goes through `atlas_dash_irc.sanitize_keys` to `herdr pane.send_input`. There is no shell, subprocess or f-string command in the new routes.
- **XSS.** `colony.js` and `channels.js` render every API string through `h()` text nodes or `setAttribute`, and `dom.js` refuses `html`/`innerHTML`/`outerHTML`. Note text, names, `log_path` and task titles are not injectable.
- **Registry and board writes.** All go through `_reg_update` (file lock plus tmp and `os.replace`) or `note()` (under the `.seq` lock); `todo add` is locked. The Colony routes only read.
- **Removed symbol `_register_worker`.** No code callers remain; only CHANGELOG history and an archived advisor todo mention it. `atlas_launch.launch` and `atlas_mux.cmd_spawn` call `register_member`.
- **Kill target safety.** `close_pane` only closes panes in `atlas-*` workspaces, and `h_colony_kill` refuses leads (`kind == "lead"`) before touching anything.

## P2 (not blocking, for the record)

- `cmd_spawn` calls `register_member` before `_tier` and `_open_window` can fail. A failed spawn leaves a registered member with no process, which shows as `running` or `stuck` in the Colony.
- `leave` and `mark_finished` call `_reg_update` without `CHANNEL_LOCK_TIMEOUT_S`. A stuck registry lock would hang a worker's exit path.
