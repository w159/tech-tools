# Removed tests of the mod redesign: classification

Scope: every test that existed at HEAD in a file under plugins/atlas whose `it(`/`test(` count dropped in the working tree, and whose name no current test file still carries. 321 tests in 43 files. Method: `git diff --name-status HEAD`, test names compared per file (`git show HEAD:<file>`), then a probe run of each HEAD file against the new rendering to see which removed tests still pass unchanged.

Classes: REMOVED-FEATURE = the test only pinned the team, core or board tab, the old strip order, or text/columns the spec deliberately removed. STILL-TRUE = the new surfaces still show the fact. Of the STILL-TRUE tests, `re-added` means this pass wrote or restored the test (file named in the last column); `covered` means a test that already exists (mostly `panel-redesign.test.ts`) asserts the same fact; `gap` means the new UI no longer shows the fact (product gap, no test weakened; see the Product gaps section).

Totals: 321 removed. REMOVED-FEATURE 111. STILL-TRUE 210: re-added 142, already covered 63, product gaps 5.

Re-added tests live in: `mod/view/panel/panel-truths.test.ts` (new, 41 tests), `panel-channel-failure`, `panel-state-clock`, `panel-toasts-cards`, `panel-team-channel-cards`, `panel-uniform-cards`, `chip-idiom-gates` (`mod/view/panel/`), `run-end-total`, `surface-polish`, `count-blocked-state` (`mod/view/`), `hud-last-outcome`, `health-metrics` (`mod/view/hud/`), `panel-side` and `panel-layout` (restored). Templated names (`${cols} ...`) stand for a loop of cases.

## Product gaps (the new UI lost a fact the old test pinned)

- G1 FIXED (`panel-gaps.test.ts` "G1: a plan row the lead closed over a failed worker reads failed"; status-tab.ts `doubted`, PLAN row and count follow the HUD doubt rule; the channel closure note is a failure too, test "channel: the closure note of a failed item is a failure"). Was: a plan row the lead closed over a failed worker reads green `✓ done` (detail `closed`) while the TEAM row of the same worker reads `✗ failed`. Repro: `scene('killed')` in `mod/surface_indices.ts`, `sidebarModel(scene('killed'), 'route', 37, UI256)` then `sidebarTree`: `✓ T3 ... (gamma-explorer)` over `closed`, and `✗ gamma-explorer failed` 3 rows lower. Old rule (critique 35): never green `done` over a dead worker; `closed` is a word the old suite banned. The HUD still has the doubt rule (`worker failed`, `DONE_DOUBT` in `mod/view/hud/hud.ts`); the panel PLAN row does not apply it.
- G2 (todo-fallback test 2, omp): the TODO box has no column for a done row's evidence (columns are ITEM STATE OWNER TIME), so `tests green` from the board is not shown. The test was re-expressed without the evidence clause. Decide if the spec meant to drop it.
- G3 FIXED (`panel-gaps.test.ts` "G3: a row that names its worker only in the title reads that worker's failure"; sidebar-model.ts `todosOf` infers the owner from the `(name)` tail as the HUD does). Was: a plan row whose worker is named only in the title (owner null, the stoprun shape of 28d53608) reads `▲ blocked` with no failure when that worker failed. With the owner set the row reads `✗` (re-added in panel-state-clock).
- G4 FIXED (`panel-gaps.test.ts` "G4: the PHASE timeline", two tests; status-tab.ts `stages`). Was: a phase that is not one of the rail phases lights the first stage (`◉ plan`); the old rule was that an unknown phase lights none.
- G5 FIXED (`panel-gaps.test.ts` "G5: the TEAM name column", two tests; status-tab.ts `teamRow` nameW). Was: the TEAM name column is capped at 24 cells (`nameW` in `mod/view/panel/status-tab.ts`), so a 29-cell name (`board-auditor-open-items-pass`) is cut to `board-auditor-open-ite…` at 80 columns where the old panel kept it whole. Real names such as `implementer-gates-and-the-long-tail` hit it.
- G7 (row 8): the HUD NOW column shows a raw tool echo: `1. toolsearch sel…` (numbered prefix kept, text lower-cased, cut inside a word) where the old LAST column stripped the `1. ` and ended on a whole word. Repro: `hudLines` with an agent `tool: '1. ToolSearch select:mcp__lean-ctx__ctx_read,mcp__lean-ctx__ctx_search'` at cols 61..150.
- Minor, not a lost test: the PLAN detail line of a failed row reads `failed · failed` when the worker's detail is the word `failed`; the gates chip on the band draws a red `■` while every other surface uses `✗`; the TEAM tally keeps the static `◐` next to turning `◓` rows (treated as a legend in the spinner test).
