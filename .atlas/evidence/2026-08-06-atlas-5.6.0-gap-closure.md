# Evidence: atlas 5.6.0 gap closure (2026-08-06)

Closes the gaps carried in ROADMAP from the 2026-08-05 and 2026-08-06 sessions.

## 1. Stale connector test (the one pre-existing failure)

The 2026-07-31 release replaced `.mcpb` launchers with vendored ESM bundles, but
`test_connectors_wiring.py` still globbed `*.mcpb`. Discovery returned nothing, so
three of its tests were vacuous and the fourth failed.

Before:
```
$ python3 -m pytest scripts/test_connectors_wiring.py -q
AssertionError: Lists differ: ['auvik', 'blumira', 'cipp', ... 'vanta'] != []
1 failed, 7 passed
```

After (discovery keyed on `mcp/<name>/server.mjs`, plus a guard that discovery is
never empty and an assertion on the real `node --import _env/load.mjs` arg shape):
```
$ python3 -m pytest scripts/test_connectors_wiring.py -q
9 passed in 0.01s
```

## 2. Gate-block persistence (facets.gate_block_count was permanently NULL)

`completion_gate.py` now records one `friction_events` row per block decision
(category `gate_block`, snippet naming the failed conditions), and
`chronicle_facet.py` counts them into `facets.gate_block_count`.

Found and fixed while wiring it: `_sync_friction_events` deleted ALL of a
session's friction_events before re-mirroring `signals`, which erased the
`gate_block` rows and `memory_capture`'s `memory_drop` rows -- neither of which
`signals` can reinsert. The delete is now scoped to the categories that hook owns.

```
$ python3 -m pytest hooks/test_chronicle_facet.py -q
13 passed in 0.07s
```

## 3. The gate's no-telemetry hole

Conditions (a), (b), (f) and (g) all key off the atlas_db run-write signal. A run
that logged nothing at all was indistinguishable from a run that wrote nothing, so
a session whose telemetry never landed got a gate enforcing only "the docs files
exist". `_run_written_paths` now falls back to the git working tree when the run
has zero events AND zero tool_calls; a run with telemetry that reports no writes is
still trusted, so a dirty tree from an earlier session still cannot block it.

```
$ python3 -m pytest hooks/test_atlas_contract.py -k CompletionGate -v
test_a_block_is_recorded_as_a_friction_event PASSED
test_gate_falls_back_to_git_when_the_db_has_no_run_row PASSED
test_gate_trusts_a_run_row_that_reports_no_writes PASSED
test_no_docs_tree_is_a_noop PASSED
test_silent_when_run_shipped_no_code PASSED
5 passed
```

## 4. .gitignore secret coverage (previously "not comprehensively verified")

Probed with `git check-ignore`. The shapes the 2026-08-05 entry left unverified
(`*.jks`, `*.keystore`, `*.p8`, `id_ecdsa`, `.git-credentials`, `secrets.yml`) were
already covered. These were NOT, and are now:

```
before: db.pgdump db.dmp dump.rdb db.bacpac db.sqlite db.sqlite3 db.db
        vault.jceks auth.keytab x.p7b   -> all TRACKABLE
after : all IGNORED
$ git ls-files | grep -Ei '\.(pgdump|dmp|rdb|bacpac|sqlite|sqlite3|db|jceks|keytab|p7b)$'
(no output -- no tracked file is lost to the new patterns)
$ git check-ignore -q docs/CHANGELOG.md README.md .atlas/findings/INDEX.md
(non-zero for each -- real docs still trackable)
```

A `GitignoreSecretContract` test now probes 24 paths on every run, so this cannot
silently regress.

## 5. skill_factory.py deleted

5.5.0 unwired `auto_skill.py` but left `scripts/skill_factory.py`, the code that
actually wrote SKILL.md files, callable by anything. Deleted with its test, and
`atlas-setup` no longer verifies it as a deployment step. A contract test asserts
no script in `scripts/` writes a SKILL.md.

## 6. Facet enrichment is now a command

`atlas_doctor.py --enrich-facet <session_id> '<json>'` validates against
`atlas_db.FACET_COLUMNS` and writes the LLM-judged columns; unknown columns and
unparseable JSON exit 2. The judgment stays the model's, the write is testable.
